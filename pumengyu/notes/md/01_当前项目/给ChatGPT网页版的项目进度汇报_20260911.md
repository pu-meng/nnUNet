# 我的肝脏/肝肿瘤分割项目进度（供后续讨论）

> 这是一份给 ChatGPT 网页版的项目交接稿。请先以其中的**证据边界**为准，不要把“有一个更高分的历史结果”直接解释为方法机制已被证明。
>
> 更新日期：2026-09-11；实验状态最后核查：2026-09-10。

## 1. 我在做什么

我在做三维 CT 肝脏与肝肿瘤分割，基于 nnU-Net/MedNeXt-L。当前候选方法名为 `MedNeXt_MLA_MoE`：

- 主干是强卷积式的 MedNeXt-L，负责局部纹理和边界；
- 在最低分辨率的 bottleneck（512 通道）后加入两个 MLA+MoE block；
- MLA 是一种低秩 K/V 的全局注意力：K/V 经过 `512→128→512` 投影，但当前实现仍计算完整 `N×N` attention，因此不能称为线性注意力；
- MoE 有 1 个共享 expert、4 个路由 expert，以 Top-2 选择融合；但代码会先计算全部路由 expert，再选择结果，因此**没有实际稀疏计算加速**；
- 解码器使用 `UpBlock → 空间形状对齐 → 与编码器 skip 逐元素相加 → decoder stage`。

这里的 token 是 bottleneck 三维特征图中的一个空间位置。我的研究动机是：局部卷积与低分辨率全局交互是否能在跨数据域肝肿瘤分割中互补；MoE 的条件特征变换是否有额外价值。

## 2. 数据、评价和“完成”的定义

我固定区分三个数据域，不做跨数据集平均排名：

| 数据域 | 用途与病例数 | 说明 |
|---|---:|---|
| LiTS / `Dataset003_Liver` | 固定 internal test，26 例（其中肿瘤阳性 23 例） | 来自 131 例公开标注队列的自定义 92/13/26 划分，不是 LiTS 官方隐藏测试集 |
| 3D-IRCADb-01 | 外部 source-only，20 例（肿瘤阳性 15 例） | 未使用 IRCADb-02 |
| HCC-TACE-Seg | 外部 source-only held-out test，21 例（全为肿瘤阳性） | 从质控后 101 例队列固定划分；无阴性病例，所以 FP rate 应写 N/A |

主排名指标为每个域单独的 Overall Dice：

`Overall = (Liver Dice（所有病例） + Tumor Dice（仅 GT 肿瘤阳性病例）) / 2`

我把一次评估称为“完成”，必须同时有：全部病例预测 NIfTI、`summary.json`、文本报告、`test_viz/` 的实际 PNG、以及 trainer/dataset/fold/checkpoint/epoch 等来源信息。仅有终端指标或仅有预测，不算完成。

## 3. 一个重要的实现问题，以及已完成的修复

旧版 MoE 在 checkpoint 包裹的 `forward()` 中原地更新路由状态（`expert_bias`、`expert_load_ema`）。这可能导致 forward 与 backward 的 checkpoint 重算使用不同状态；DDP 下每张卡也可能只根据本地 token 负载更新。

已修复为：

1. `forward()` 仅收集本 iteration 的临时 expert 计数，不改持久状态；
2. backward/checkpoint 重算结束后，每 iteration 只提交一次 bias/EMA 更新；
3. DDP 下提交前用 `all_reduce(SUM)` 汇总所有 rank 的 expert 计数。

已经通过 6 项定向回归检查，并且完成了真正的两卡 DDP 从头训练。因此，下面标记为“修复后”的结果来自修复后的代码，不是从旧 checkpoint 续训。

## 5. 历史上看起来更好的结果，为什么现在不能当正式结论

修复前的历史结果曾显示：`MedNeXt_MLA_MoE` 在 IRCADb Overall 0.8511、Tumor Dice 0.7349，且相对 MedNeXt 的 Tumor Dice 差异曾为 `+0.045`（Holm p=0.0229）。另一个带 SizeOV4 的历史版本在 LiTS / IRCADb / HCC Overall 为 `0.8591 / 0.8479 / 0.6356`。

但这些都是**路由修复前**的谱系；而且 SizeOV4 会同时改变病例采样/暴露节奏，不能证明 MoE 机制本身。修复后 MLA+MoE 没有复现旧 IRCADb 优势。因此它们可以作为“为什么需要重训核验”的历史线索，不能再作为论文的正式机制证据或主排名依据。

## 6. 现有证据支持什么、不支持什么

目前可以较稳妥地说：

- MedNeXt 是这个任务上强的卷积主干；
- 将全局交互放在低分辨率 bottleneck 有合理的工程/建模动机；
- 三数据域的外部评价与病例级失败分析可用于研究不同域的表现边界；
- 修复后的 MHA+MoE、MLA+MoE 已具备可追溯、可复核的完整三域交付；
- 结果存在明显域依赖，不能把单个外部域的提高推广为普遍泛化能力。

目前不能说：

- MLA+MoE 已普遍提升外部可靠性；
- MoE 已形成可解释的专家分工，或其提升来自“条件路由”而非额外参数容量；
- Top-2 带来了实际稀疏计算加速；
- 修复前的高分已经被修复后训练复现；
- 现在已经有严格统一条件、足以做因果归因的完整 MHA/MLA × MLP/MoE 消融。

## 7. 当前最大的科学缺口与建议的下一步

最关键的不是继续堆模块，而是先回答“MoE 是否真的有独立贡献”。目前有两个缺口：

1. **容量混杂**：MLA+MoE 约 73.735M 参数，纯 MLA 约 67.429M；如果没有参数匹配的 dense FFN 对照，MoE 的任何差异都可能只是额外容量。
2. **训练稳定性不足**：目前核心结果主要是 fold 0 的单次训练。病例级 bootstrap 只能说明同一训练下病例差异的不确定性，不能替代多随机种子或多 fold。

我倾向的下一步顺序是：

1. 先实现并验证 parameter-matched dense control：固定 MLA、训练设置和总参数量，只把 MoE 换成不含 router/专家选择的 dense FFN；一个候选是每个 block 使用 `512→5120→512` 的 dense FFN，参数量与 5 个半宽 MoE expert + router 近似匹配。
2. 三域完整评估该 dense control，并与修复后 MLA+MoE 做同样的病例级配对统计。
3. 只有 MoE 在该容量对照下仍表现出有意义且稳定的跨域增益，才继续多 seed/多 fold，并把 MoE 保留为论文主贡献。
4. 如果 dense control 相当或更好，或多 seed 后优势消失，应把 MoE 降级为容量/交互分析或负结果；论文重心回到“低分辨率全局交互的跨域边界”，而不是宣传 MoE 提升可靠性。
5. SizeOV4 可以作为采样策略对照继续做，但它不应被用来证明 MoE 的机制收益。
