# 方法论文的研究问题定义与创新来源

> 记录日期：2026-08-29  
> 记录性质：论文阅读与研究方法论笔记  
> 证据范围：UNETR、ConvNeXt、MedNeXt、Swin UNETR、nnU-Net 和 MedSAM 的表述基于原文摘要/引言核对；U-Net、Transformer、ViT、Swin Transformer 和 SAM 为后续补充的问题定义归纳；本笔记不等同于系统文献综述

## 1. 核心结论

> **“定义问题”不等于“必须分析具体失败病例”。**

很多顶尖方法论文确实没有从 case-level failure analysis 出发。它们定义的问题常常位于更抽象的方法、设计空间、技术范式或系统层。数据集在这类工作中主要用于验证研究命题，不一定是发现问题的起点。

因此，以下两个判断需要同时成立：

1. 说“这些论文完全没有定义问题”过于绝对。
2. 说“它们都通过分析具体失败病例来定义问题”也不符合原文。

真正的分歧在于：日常讨论中的 `problem` 可能指广义的 research problem，而自己之前理解的 `problem` 更接近“从具体数据或病例中归纳出的稳定失败模式”。

## 2. 四种创新起点

### 2.1 Failure-driven

起点是可重复观察的具体失败现象：

```text
具体失败现象
→ 分析稳定失败模式
→ 定义可验证的任务问题
→ 设计针对性方法
```

例如：小肿瘤漏检、无肿瘤病例假阳性、跨域性能骤降。这是导师要求开展失败病例分析时指定的创新来源，但不是唯一合法的研究路线。

### 2.2 Limitation-driven

起点是现有方法的结构性限制：

```text
现有方法的结构限制
→ 受限的表征或能力
→ 选择能补足该能力的机制
→ 新架构
```

UNETR 是典型例子：将卷积的局部性与长距离空间依赖建模受限联系起来，再引入 Transformer encoder。这是明确的 method-level problem，并不需要以某类失败 CT slice 作为起点。

### 2.3 Opportunity / paradigm-driven

起点是新技术、新设计原则或新范式带来的可研究空间：

```text
新技术或新设计空间
→ 提出研究命题
→ 系统地现代化或重组旧范式
→ 通过 benchmark 验证
```

ConvNeXt 的问题不是“CNN 在哪些图片上失败”，而是“纯 ConvNet 在吸收 Transformer 时代的现代设计后，能否继续与 Transformer 竞争”。Swin UNETR 的 self-supervised pretraining 工作也带有明显的机会驱动特征：将 SSL 与 Swin Transformer 在 3D 医学影像中组合并验证。

### 2.4 System-level problem-driven

起点是领域整体工作流或能力边界中的问题：

```text
领域工作流缺陷
→ 定义系统级目标
→ 构建可复用的方法或平台
→ 在多数据集/多任务上验证
```

nnU-Net 针对不同数据集需要专家手工配置流水线的问题，通过 dataset fingerprint 自动配置预处理、网络、训练和后处理。MedSAM 针对医学分割模型过于 modality-specific 或 disease-specific、缺少跨任务泛化能力的问题，提出通用医学分割基础模型。

## 3. 十一篇代表论文的问题定义

下表不是对每篇论文所有贡献的概括，而是为了识别其最主要的研究命题及所在层级。

| 论文 | 它真正定义的问题 | 问题层级 |
|---|---|---|
| **U-Net** | 标注医学图像很少，如何在少量训练样本下仍实现精确定位和分割？ | 任务 + 方法 |
| **Transformer** | 序列建模是否必须依赖 recurrence 或 convolution？能否只使用 attention？ | 范式级方法问题 |
| **ViT** | 图像识别是否真的必须依赖 CNN？纯 Transformer 能否直接处理 image patches？ | 范式级方法问题 |
| **Swin Transformer** | Vanilla ViT 不适合作为通用视觉 backbone：高分辨率计算贵，且视觉目标尺度变化大，如何解决？ | 架构级方法问题 |
| **ConvNeXt** | Transformer 的优势究竟来自 Transformer 本身，还是现代 architecture design？纯 CNN 现代化后能达到什么程度？ | 设计空间问题 |
| **UNETR** | 3D segmentation 中卷积的局部性限制 global / long-range dependency 建模，Transformer 能否作为 encoder？ | 方法 limitation |
| **Swin UNETR** | 大规模 3D 医学标注昂贵，能否用 self-supervised pretraining + hierarchical Transformer 学习可迁移的 3D anatomy representation？ | 数据稀缺 + 方法 |
| **nnU-Net** | 为什么医学分割方法换一个数据集就需要大量专家手工配置？能否让 pipeline 根据数据集自动配置？ | 系统级问题 |
| **SAM** | 能否把 segmentation 从大量固定任务统一成一个 promptable task，并实现 zero-shot transfer？同时如何获得足够大规模的 segmentation data？ | 范式 + 数据系统 |
| **MedSAM** | 医学分割模型通常针对特定 modality 或 disease，能否构建跨模态、跨疾病的通用医学分割 foundation model？ | 系统/泛化问题 |
| **MedNeXt** | Transformer 很强，但在医学数据有限的条件下，现代纯 ConvNet 能否通过 large kernel + scaling 达到强性能？ | 方法设计空间 |

## 4. 对其中六篇论文的进一步理解

### UNETR

原文明确将 FCNN 的卷积局部性视为长距离空间依赖学习的限制，因此它不能被描述为“没有定义问题”。它的问题是方法层限制，而不是小肿瘤等任务层失败。

### ConvNeXt

它研究的是 architecture design space：Transformer 的优势究竟来自 attention 本身，还是一整套现代架构设计？作者从 ResNet 出发，逐步引入 Transformer 时代的设计并观察贡献。因此，ImageNet 在这里主要是 benchmark，而不是失败现象的发现地。

### MedNeXt

它的问题是如何将现代 ConvNet 与 scaling 思想适配到数据稀缺的 3D 医学分割。large kernel、ConvNeXt-like block、residual up/downsampling、kernel scaling 和 compound scaling 是对该方法空间问题的回答。这不是对某类 CT 肿瘤失败的专项研究。

### Swin UNETR

这项工作同时使用大规模专家标注 3D 数据集难获得的 limitation，以及 SSL + Swin Transformer 的新技术机会。其核心更接近“构建一个 3D 医学影像自监督预训练框架并验证”，而不是查找特定分割失败模式。

### nnU-Net

它是明确的 problem-motivated methodology：生物医学分割流水线高度依赖数据集属性与硬件条件，专用方案的手工设计困难、成本高且不易复现。它解决的是流水线配置问题，不是单一 lesion failure。

### MedSAM

它针对的是现有医学分割方法通常只服务于特定模态或疾病、缺少跨任务泛化能力的系统级问题。其大规模多模态数据用来支撑 universal medical image segmentation 这一研究目标。

## 5. 对当前课题的含义

不应把顶尖 method paper 的论文生成路径误读为“每篇都先完成病例级 failure analysis”，也不应因为某篇论文没有这样做就判断它“没有问题”。

导师要求分析失败病例，是在为当前课题指定一条更具体、更容易建立数据证据链的 **failure-driven problem discovery** 路线。这是适合当前肝肿瘤分割课题的创新来源，不是对所有方法研究的统一要求。

与导师或学姐讨论时，可以使用下面这个更精确的表述：

> 我以前说顶尖方法论文“不定义问题”不准确。现在我的意思是：很多顶尖 method papers 不做 case-level failure-driven problem discovery，它们的问题通常来自方法限制、设计空间或新的技术范式；而老师让我做的，是另一种从数据和 failure 中发现具体问题的研究路线。

## 6. 后续使用时的判断问题

阅读一篇新论文时，不再只问“它有没有问题”，而是分别问：

1. 它的 research problem 是任务层、方法层、范式层还是系统层？
2. 问题的证据来自病例失败、已知结构限制、新技术机会，还是领域工作流缺陷？
3. 数据集是用来发现问题，还是主要作为 benchmark 验证命题？
4. 论文的方法是否真正对应前面定义的问题？
5. 实验能否区分“方法有效”与“对问题的解释正确”？

## 8. 当前个人目标：建立“问题—结构—证据”闭环

> 追加日期：2026-08-30  
> 当前目标：不是继续堆叠现成模块，而是找到一个真实、具体、可验证的问题，围绕它设计由自己规定内部数据流的核心机制，再用针对性实验证明该机制解决的正是所声称的问题。

目前已经具备的基础包括：

- 有成熟的 baseline / backbone；
- 能够修改网络并运行实验；
- 能够进行不同模型和 trainer 的比较；
- 已经开始分析 failure、小肿瘤和跨数据集问题。

当前真正需要补齐的是下面的完整闭环：

$$
\boxed{
\text{明确问题}
\rightarrow
\text{针对问题设计核心结构}
\rightarrow
\text{用实验形成直接证据}
}
$$

### 8.1 第一优先级：先找到并固定一个可验证的问题

当前最近的目标不是立即发明模块，而是先找到一个能够写进 Introduction、也能够被实验推翻的问题。问题不能只写成：

> 我想提高 Dice。

它至少需要包含：

1. **具体对象**：哪类病例、病灶尺度、数据域或系统环节存在问题；
2. **稳定现象**：问题能否在多个病例、trainer、随机种子或数据域中重复观察；
3. **候选原因**：现有结构或监督机制为什么可能导致该现象；
4. **可证伪预测**：如果解释正确，针对性干预后哪些指标或病例亚组应该改善；
5. **边界条件**：什么结果出现时，应承认原解释不成立。

例如，下面只能作为候选问题模板，不能在没有证据时直接写成结论：

> 现有模型在小肿瘤上的表现显著弱于大肿瘤；如果主要原因是多次下采样造成细粒度病灶特征丢失，那么保留高分辨率局部信息的针对性机制应主要改善 small-lesion 指标，而不是只带来无差别的总体 Dice 波动。

或：

> Encoder 与 decoder 特征对不同尺度病灶的有效贡献可能不同；如果固定 skip fusion 是限制因素，那么自适应融合机制的收益应随病灶尺度或错误类型呈现可解释差异。

Small lesion、skip fusion、跨数据集监督冲突目前都是候选入口，尚未固定为最终论文问题。最终选择应由失败证据、现有方法限制、文献空缺和可执行实验共同决定。

#### 8.1.1 可以宽松找，但不能随便编

问题不必是全领域最重大、最新或最复杂的问题。为了尽快形成可发表闭环，可以优先选择最容易稳定复现、最容易设计针对性机制、也最容易进行分组验证的问题。可接受的候选包括：

- 小肿瘤表现明显弱于大肿瘤；
- 模糊边界区域误差较大；
- 高层语义与低层细节采用固定融合，无法根据病例或尺度调整贡献；
- 多尺度目标下单一感受野表现不稳定；
- 跨数据集性能明显下降；
- 某类病例或病灶容易漏检。

这些问题可以普通，但不能是先决定模块以后才编造出来的理由。一个“够用的问题”至少满足三个硬条件：

1. **Baseline 中真实存在**：能够由指标、病例或可视化稳定观察，而不是依靠主观挑图；
2. **机制直接对应**：模块中的关键设计能够逐项对应候选原因，例如 small lesion 对应高分辨率 detail branch，多尺度问题对应 scale-aware fusion；
3. **能够单独验证**：除 Overall Dice 外，还能通过分组指标、消融或配对病例判断目标问题是否真的改善。

因此，问题筛选时采用的功利标准是：

> **问题不一定很重大，但必须真实、可复现，并且能够被核心机制直接改善。**

“问题不新”本身不等于不能发表。很多方法论文研究的是已有问题，其主要新意来自：针对这个问题提出了新的、具体的机制。但如果 Baseline 中看不到该问题，或实验无法区分目标机制与普通涨点，就不能为了配合已经想好的模块硬写问题动机。

#### 8.1.2 最短的现实执行路线

```text
先获得可信的 Baseline 结果
→ 从真实结果中寻找最容易稳定复现的问题
→ 固定问题、候选原因和可证伪预测
→ 围绕它设计一个自己的核心机制
→ 做公平对照、机制消融和对应的分组指标
→ 对应关系成立后再进入论文写作
```

这里的“开始写论文”不是只要 Overall Dice 上涨就成立，而是至少已经看到：Baseline 中问题存在、目标亚组按预期改善、关键机制消融支持解释，并且没有用总体平均掩盖明显退化。

### 8.2 第二步：设计真正属于自己的核心机制

“自己的模块”不要求发明全新的卷积、注意力或数学运算。原创性可以来自作者自己规定：

- 模块接收什么输入以及输入来自网络哪一层；
- 数据分成几条路径，每条路径负责什么信息；
- 特征之间如何交互，权重如何生成；
- 不同尺度、局部和上下文信息如何融合；
- residual 如何连接；
- 输出送到哪里，以及为什么能影响目标问题。

因此，一个核心原创模块就可能足够。评价重点不是框图中有多少组件，而是内部 tensor flow 是否由问题推导出来、每一步是否有清楚作用，并且是否能通过消融验证。不能把多个现成模块拼接后统一称为原创机制。

### 8.3 第三步：证明机制解决的就是所声称的问题

如果声称解决 small-lesion failure，证据不能只有总体 Dice 上升，还应至少比较：

| 方法 | Small lesion | Medium lesion | Large lesion | Overall |
|---|---:|---:|---:|---:|
| Baseline | 待测 | 待测 | 待测 | 待测 |
| Baseline + proposed mechanism | 待测 | 待测 | 待测 | 待测 |

理想证据模式是：目标亚组显著改善，非目标亚组没有明显受损，并且改善能够在配对病例、可视化和消融中被追踪。若各尺度只出现近似一致的小幅波动，则证据更支持“整体正则化或容量变化”，不能直接归因于解决了小肿瘤问题。

针对任何候选问题，最终证据至少应覆盖：

- Baseline 与核心机制的公平对照；
- 核心路径、权重或融合方式的消融；
- 与问题直接对应的分层指标；
- 配对病例及失败案例变化；
- Liver、Tumor、Overall 与各数据域结果，避免总体均值掩盖退化；
- 参数量、计算量、显存或训练成本；
- 完整预测、`summary.json`、文本报告、可视化和 checkpoint provenance。

### 8.4 当前阶段的完成标准

只有同时完成以下三项，才形成一项可交付的方法论文工作：

1. **问题成立**：有重复、分层且可审计的证据证明问题真实存在；
2. **结构对应**：核心机制中的每条主要数据流都能对应问题假设，而不是事后解释；
3. **证据闭环**：针对性实验表明目标问题得到改善，并如实报告无效、退化、成本和适用边界。

当前阶段的第一完成点是：

> **先从 failure-driven、method/system-driven 或 paradigm/field-driven 入口中，找到并固定一个满足上述条件的具体问题。**

### 8.5 一句话目标

> **我的目标不是再拼三个模块，也不是只让总体 Dice 偶然上涨，而是完成一个“真实问题—自有核心结构—针对性证据”的闭环；当前最优先的任务，是先找到那个值得解决且能够验证的问题。**

更现实的执行原则是：

> **问题可以普通，但不能假；模块可以借鉴已有思想，但内部数据流和组合方式要有自己的设计；实验必须证明它确实解决了这个问题。**

## 9. 当前 MedNeXt_MLA_MoE 项目的问题收束

### 9.1 可以借鉴的研究组织方法

当前项目应保留下列闭环：

```text
问题现象
→ 机制假设
→ 结构设计
→ 针对性证据
```

但不应把“小肿瘤、弱边界、跨数据集可靠性”直接包装成 MLA+MoE 已经解决的三个问题。需要先根据 MedNeXt 已有能力和当前模块的真实作用范围约束表述。

MedNeXt 已具有 U 形多尺度层级、大核 depthwise convolution、inverted bottleneck、残差上下采样和通道混合，因此不宜笼统声称它“没有多尺度”、“感受野太小”、“没有通道交互”或“不能学习边界”。更准确的出发点是：

> MedNeXt 能够通过层级卷积扩大感受野，但距离较远的三维空间位置之间仍需经过多层局部卷积间接传递信息。

这一方法限制能够支持在最低分辨率 bottleneck 中引入 MLA，但不能自动证明 MLA 已经解决小肿瘤或弱边界问题。

### 9.2 一个中心问题，而不是三个松散问题

当前最适合的中心问题是：

> **在保留 MedNeXt 强局部卷积表征的前提下，最低分辨率全局交互与条件前馈变换能否形成有效互补，其作用在不同肝肿瘤 CT 数据域中是否稳定？**

该中心问题可以拆成三个子问题：

1. **结构互补**：MedNeXt 的远距离空间关系仍通过多层局部运算间接传播；在最低分辨率加入显式全局交互是否具有增量价值？这一问题对应 MLA。
2. **条件变换**：标准 MLP 对所有空间 token 使用同一组前馈参数；引入 shared/routed experts 后，输入依赖的条件特征变换是否优于固定 dense MLP？这一问题对应 MoE-FFN。
3. **数据域依赖**：MLA、MoE 及其组合的收益能否在不同数据域中保持，还是会随病灶分布、成像特征和标注来源变化？这是评价问题和作用边界，不是第三个模块。

二者的论文逻辑为：

```text
局部卷积骨干
→ 最低分辨率全局补充
→ 条件特征变换
→ 通过多数据域验证作用及其边界
```

### 9.3 小肿瘤、弱边界和误报的当前定位

| 失败维度 | 当前用途 | 何时才能升级为核心问题 |
|---|---|---|
| 小肿瘤 | 按 lesion size 分层比较 Dice、recall 和漏检 | MLA+MoE 的收益稳定集中于小病灶，并有与结构一致的机制解释 |
| 弱/模糊边界 | 使用 HD95、Surface Dice 或低对比度分层观察变化 | 引入真正针对边界的机制，并完成相应消融 |
| 无肿瘤误报 | 作为 IRCADb 病例级可靠性指标 | 在足够多的阴性病例中证明稳定降低 FP，而不是少量病例波动 |
| 跨数据域下降 | 检验 MLA/MoE 作用范围和可靠性 | 多域结果和重复实验稳定后，才能进一步讨论泛化机制 |

当前 MLA 位于最低分辨率 bottleneck，没有直接保护高分辨率小病灶特征；当前模型也没有显式的 gradient/Hessian 分支、boundary supervision 或 boundary-aware decoder。因此，小肿瘤和弱边界应先作为检验现有方法的失败分层，不能直接写成 MLA+MoE 已解决的贡献。

### 9.4 当前证据边界

现有三数据域结果更适合支持“组合作用具有数据域依赖性”，不支持“MLA+MoE 统一提升外部泛化”。在归因 MoE 之前，仍需要：

- 完成修复后正式重训和 checkpoint 来源核验；
- 保留 MHA/MLA × MLP/MoE 控制变量比较；
- 补充 parameter-matched dense control，排除单纯参数量增加的解释；
- 对 MoE 路由进行专家负载和专门化分析，不预先声称已形成可解释分工；
- 将小病灶、边界、漏检和误报按病例配对分析，不用 Overall Dice 代替机制证据。

因此，当前项目不需要为了凑“三个问题、三个模块”再强行增加小病灶或边界模块。更稳妥的主骨架是：

> **全局交互是否补充 MedNeXt + MoE 条件变换是否带来增量 + 二者的作用是否具有数据域依赖性。**

## 10. 代表方法、母问题与 MedNeXt 候选研究问题补充整理

> 补充日期：2026-09-04
>
> 记录来源：对话中提供的论文与问题归纳。
>
> 证据边界：本节是用于选题和构造假设的工作性整理，其中新增论文尚未在本轮逐篇核对原文。正式写入论文的相关工作、动机或引用前，应回到原文摘要、引言和方法部分复核，不将本表当作已完成的系统文献综述。

### 10.1 代表论文主要在解决什么问题

| 论文 / 模型 | 它主要认为的问题 | 核心解决思路 | 问题类别 |
|---|---|---|---|
| **U-Net** | 下采样后空间细节丢失，语义和定位难兼顾 | encoder-decoder + skip connection | 多尺度 / 定位 |
| **nnU-Net** | 医学分割中大量性能差异来自训练、预处理、patch 和后处理配置不合理 | 自动配置整个 pipeline | 训练配置 / 工程系统 |
| **DynUNet** | 不同数据集的尺寸、spacing 和 patch 差异很大，固定结构不合适 | 根据 spacing / patch 自适应构造网络 | 数据适配 / 配置 |
| **SegResNet** | 深层网络训练困难，普通卷积块表达受限 | residual block | 优化 / 表征能力 |
| **UNETR** | CNN 以局部建模为主，长距离空间依赖建模受限 | Transformer encoder + CNN decoder | 全局上下文 |
| **SwinUNETR** | 标准 Transformer 全局注意力计算过重 | shifted window attention，局部窗口逐步交换信息 | 全局上下文 + 效率 |
| **UNETR++** | Transformer 计算较重，同时希望建模空间和通道关系 | EPA：spatial + channel attention | 全局关系 + 效率 |
| **nnFormer** | 3D 医学图像的长程空间依赖以及局部与全局融合不足 | Transformer-based encoder/decoder | 全局上下文 |
| **MedNeXt-v1** | 纯 CNN 的 scaling 和现代化设计不足，传统小核 CNN 表征有限 | ConvNeXt-style block、depthwise convolution、inverted bottleneck 和大核 | 卷积表征 / scaling |
| **MedNeXt-v2** | 大型 3D CNN 的 scaling、预训练和稳定优化仍有不足 | GRN、深度/宽度/上下文 scaling、大规模预训练 | 可扩展性 / 表征学习 |
| **EfficientMedNeXt** | MedNeXt decoder 高分辨率部分计算冗余，模型较重 | 精简 decoder、调整通道、引入多感受野 | 效率 |
| **STU-Net** | 3D 医学分割模型规模化、迁移性和预训练不足 | scalable U-Net + supervised pretraining | 规模化 / 泛化 / 迁移 |
| **EffiDec3D** | 3D decoder 的计算和显存代价高 | 更高效的 decoder | 效率 |
| **G-UNETR++** | 边界/几何信息利用不足、Transformer 复杂度高且存在类别不平衡 | Hessian/梯度 encoder + hybrid loss | 边界 / 几何 + 类别不平衡 |
| **SegVol** | 传统模型通常是 task-specific，泛化较弱，缺少统一交互式/通用分割能力 | foundation model / prompt-based segmentation | 泛化 / 通用性 |
| **Vista3D** | 3D 医学图像任务、器官和病灶类型多，单任务模型泛化不足 | 通用 3D segmentation + prompt | 跨任务 / 泛化 |
| **SAM / MedSAM** | 每个分割任务单独训练的代价高，zero-shot 和 promptability 不足 | promptable segmentation | 通用性 / 交互 |
| **ResEnc-L / nnU-Net revisited 一类** | 许多所谓“新模块提升”可能来自模型容量或训练预算不同 | 强 residual encoder + 统一配置下的严格比较 | 强 baseline / 公平评测 |

这个表的主要用途不是按模型年代堆叠文献，而是追问每篇论文将什么定义为主问题、使用什么结构回答、以及问题处于任务、方法、效率还是系统层。

### 10.2 可将大量论文压缩成的八类母问题

#### 10.2.1 表征能力不足

包括局部感受野、长程依赖、全局上下文、通道交互、空间关系和多尺度表示不足。其共同问题是：

> 现有 feature representation 还不足以表达任务需要的关系，如何增强特征表达？

代表方向包括 UNETR、SwinUNETR、UNETR++、nnFormer 和 MedNeXt。

#### 10.2.2 边界与几何信息不足

包括 fuzzy boundary、low contrast、partial volume、不规则形状、器官/肿瘤边界模糊以及未显式利用几何结构。核心问题是：

> 模型可能能够分出主体，但边缘和形状还不够准确。

常见方向包括 edge-aware、boundary-aware、Hessian 和 gradient 类方法。

#### 10.2.3 小目标与小病灶

典型现象包括 small lesion 信号弱、体积占比低、经过下采样后消失、lesion-level recall 低，以及 Dice 容易被大目标主导。其核心是：

> 小目标信号弱且占比低，容易在深层表征中消失。

#### 10.2.4 类别不平衡

包括 background 过多、liver 相对 tumor 过大、tumor voxel 太少和 negative cases 主导优化。其本质是：

> 优化目标被多数类支配。

常见回答包括 Dice、Focal、Tversky、Unified Focal 和 lesion oversampling，但必须区分损失/采样改动与结构改动。

#### 10.2.5 多尺度不足

一种 kernel size 难以同时服务小病灶的细粒度表征和大器官的广域上下文，不规则肿瘤也存在明显尺寸跨度。常见方向包括 ASPP、dilation、multi-branch、pyramid、large kernel 和 hierarchical feature fusion。核心问题是：

> 不同尺寸目标难以依靠单一尺度统一处理。

#### 10.2.6 计算效率、显存与模型复杂度

包括 Transformer 的二次复杂度、3D feature 过大、decoder 过重以及参数量/FLOPs 过高。核心问题是：

> 限制不一定是精度不足，也可能是方法代价过高。

#### 10.2.7 数据集差异与泛化

包括 scanner、spacing、protocol、contrast phase、population 和 annotation policy 的差异。核心问题是：

> 训练集内部表现好，不代表更换数据域后仍然可靠。

外部验证不应只比较总 Dice，还应追问哪些失败在 domain shift 下变化最大。

#### 10.2.8 标注歧义与 annotation inconsistency

包括不同医生的边界差异、tiny lesion 是否纳入、necrosis 是否归入肿瘤、vessel invasion 的标注方式以及模糊病灶边界。核心问题是：

> Ground truth 本身可能不是唯一且绝对的真值。

这一类问题比普通模块论文更接近数据、标注语义和可靠性研究。

### 10.3 为 MedNeXt 选问题时的 baseline-aware 约束

MedNeXt 已经通过 depthwise convolution、inverted bottleneck、ConvNeXt-style block、large kernel、3D U-Net hierarchy 以及深度/宽度/核尺寸 scaling 增强卷积表征。因此，对它的批评需要比“CNN 特征提取太弱”、“感受野太小”或“没有多尺度”更具体。

候选问题不应从 global context、gradient、channel、multi-scale、edge 和 imbalance 中随机挑选，而应对应 MedNeXt 在当前数据上可重复的失败，并且三个问题之间最好存在同一条因果或证据链，而不是三项互不相干的模块。

### 10.4 六个值得验证的 MedNeXt 候选问题

#### 候选 1：小肿瘤信息在深层传递中衰减

不只写“small lesion difficult”，而应将现象具体化为：

> MedNeXt 在多次下采样和深层特征抽象过程中，小病灶的局部信号可能逐渐被大范围肝脏语义淹没。

可导向 high-resolution branch、small-lesion-preserving skip、multi-scale lesion enhancement 或 fine-detail branch。

#### 候选 2：局部卷积扩大理论感受野，但远距离交互仍然间接

理论感受野的增大不等于有效的全局交互：

\[
\text{theoretical receptive field}
\neq
\text{effective global interaction}
\]

可检验的问题是：

> MedNeXt 能扩大 receptive field，但 distant voxel interaction 仍然通过多层局部卷积间接传播。

可导向 bottleneck global attention、low-rank attention、MLA、state-space/linear attention 或 axial/strip interaction。

#### 候选 3：弱或模糊边界信息未在深层表征中稳定保留

不能声称“CNN 不能学习梯度”，因为卷积完全可以隐式编码局部导数。更稳妥的表述是：

> Although convolution can implicitly encode local derivatives, boundary-sensitive information may not be consistently preserved and exploited through deep feature abstraction.

可导向 boundary-guided feature、gradient/Hessian branch、boundary-aware decoder 或 edge supervision。对应证据应包括 boundary stratification、low-contrast subgroup、HD95、Boundary Dice 或 Surface Dice。

#### 候选 4：通道混合存在，但缺少显式的样本自适应重标定

MedNeXt 的卷积本身已经完成 channel mixing，所以不能说“没有 channel interaction”。可候选地表述为：

> 卷积中的 channel mixing 主要由训练后固定的参数完成，对不同病例缺少显式的输入依赖型通道重标定。

可导向 channel attention、EPA-like interaction、dynamic gating 或 MoE，但它的任务价值需要与小病灶、误报或跨域失败建立实证联系。

#### 候选 5：跨数据集性能下降和外部可靠性不足

不停留在“domain shift 存在”，而应进一步追问：

> 同一个 MedNeXt 在内部数据上表现良好，但在外部数据上究竟是哪类病灶、边界或误报失败增加最明显？

可分析 small lesions、low-contrast lesions、atypical intensity 和 boundary ambiguity 在外部域中的变化。

#### 候选 6：无肿瘤病例误报

很多肿瘤分割 benchmark 主要包含肿瘤阳性病例，或者主要在 positive cases 上计算 Dice，容易弱化对 false-positive burden 的评估。临床可靠性可补充：

- false-positive lesion count；
- false-positive volume；
- case-level specificity；
- 阴性病例中是否产生任何肿瘤预测。

若当前测试集没有阴性病例，这类指标应记为 `N/A`，不得把 `0/0` 描述为无误报。

### 10.5 候选问题应连成一条逻辑链

三个候选问题最好不是彼此独立的“channel attention + class imbalance + FLOPs”，而是形成可验证的相互关系。例如：

\[
\boxed{
小肿瘤
\rightarrow
边界/局部细节弱
\rightarrow
深层卷积与跨域条件下进一步丢失
}
\]

或者：

\[
\boxed{
局部表征限制
+
小肿瘤失败
+
外部泛化下降
}
\]

也可以从三个层级组织研究：

| 层级 | 候选问题 | 可对应的方法/证据 |
|---|---|---|
| 模型层 | MedNeXt 的远距离/全局信息交互仍依赖多层局部卷积传播 | bottleneck global module |
| 目标层 | small/low-contrast tumor 在层级下采样和特征抽象中容易丢失 | small-lesion/boundary-preserving mechanism |
| 可靠性层 | 上述 failure 可能在 external datasets/domain shift 下进一步放大 | 外部验证与分层失败分析 |

这一三层组织是候选研究框架，不等于当前 MLA+MoE 已经对应解决了三层问题；对当前项目的具体收束仍以第 9 节为准。

### 10.6 先把候选问题跑成数据

正式确定问题以前，应对可信 MedNeXt baseline 进行分层评估，不只查看平均 Dice：

| 分组 | 优先指标 |
|---|---|
| small lesion | Dice / lesion-level recall |
| medium lesion | Dice / lesion-level recall |
| large lesion | Dice / lesion-level recall |
| low boundary contrast | Dice / HD95 / Surface Dice |
| high boundary contrast | Dice / HD95 / Surface Dice |
| internal dataset | Liver / Tumor / Overall Dice |
| external dataset | Liver / Tumor / Overall Dice + 失败类型变化 |
| tumor-negative cases | FP lesions/case / FP volume / case-level specificity |

数据可能推翻事先猜想。例如，若结果显示小病灶、低对比度和阴性病例误报是稳定问题，而 global-context 相关假设没有直接证据，就应调整选题，而不是为了保留预设模块强行解释。

### 10.7 从选题到论文主体的五步路线

#### Step 1：将 MedNeXt baseline 跑扎实

不只查看平均 Dice，还要核对 checkpoint provenance、预期病例、完整预测、`summary.json`、文本报告和 `test_viz/` PNG。

#### Step 2：找到三个稳定 failure

用病灶尺度、边界对比度、数据域、阳/阴性病例以及错误类型定义可量化的 \(F_1,F_2,F_3\)。“三个”是候选整理方式，不是必须凑够的数量指标；一个足够重要且可证伪的中心问题也可以构成论文主体。

#### Step 3：为每个 failure 提出机制假设

例如，对“small-lesion recall 低”提出“多次下采样造成高分辨率局部信号丢失”的可证伪假设，并提前规定什么结果会推翻该解释。

#### Step 4：设计直接对应问题的模块

小病灶保留假设应对应高分辨率信息路径；多尺度问题应对应 scale-aware interaction；远距离交互限制才能直接对应 global module。模块的输入、位置、数据流和输出必须能够逐项回答前面的假设。

#### Step 5：证明改善发生在理论上应该改善的地方

不以“Overall Dice +1%”作为唯一证据。如果声称解决小肿瘤，更有力的证据应是 small-lesion recall 明显改善，large-lesion 性能基本不变，并能在配对病例、可视化和关键消融中追踪到改善来源。

### 10.8 本节可直接复用的选题提醒

> 不要先问“还有什么新模块可以加”，而应先问“MedNeXt 在当前数据上，哪些病例、病灶或错误类型失败得最稳定”。

\[
\boxed{
\text{Failure}
\rightarrow
\text{Mechanism Hypothesis}
\rightarrow
\text{Module}
\rightarrow
\text{Targeted Ablation}
}
\]

“小肿瘤 + 弱/模糊边界 + 跨数据集可靠性”是与肝肿瘤任务相符的优先验证候选，但它们仍是需要用 baseline 分层数据验证的候选问题，不是当前方法已经建立的三项结论。
