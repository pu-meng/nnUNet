# 1. 官方赛题标准与硬性要求

## 1.1 题目名称

**可自学习的 AOI 实时在线 AI 质检**

AOI = **Automated Optical Inspection，自动光学检测**。

这里的 Optical 指通过工业相机等光学成像设备获得 RGB、灰度、红外等图像或视频，再进行自动检测；不是“可选”的意思。

## 1.2 官方任务目标

在制造业组装过程中，对屏幕、电池、中框等组件进行实时监测，尽早拦截不良事件。

系统需要处理：

- 图片输入；
- 视频输入；
- 正常与异常模式识别；
- 新缺陷的少样本或无样本启动；
- 用户反馈后的动态优化。

## 1.3 官方要求覆盖的异常类型

系统需要尽可能覆盖：

1. **尺寸偏差**
2. **缺件、少件**
3. **逻辑错误**
   - 例如装配顺序错误；
4. **色彩变化**
5. **常见外观缺陷**
   - 例如划痕、污渍、破损、异物等；
6. **图片和视频两种输入场景**

注意：

> 官方文档没有限定只能做分类、目标检测或分割。最终输出形式和评测指标仍需结合后续官方说明确认。

## 1.4 实时性硬约束

对于 **2500 × 2500** 输入图片：

- 在 **RTX 2060 或以下 GPU** 上，模型运行时间要求 **小于 200 ms**；
- 挑战目标：在 **CPU** 上运行时间 **小于 2 s**。

必须单独统计：

```text
图像读取/解码
预处理
模型推理
后处理
总耗时
```

在官方未进一步说明前，不得擅自假设“200 ms 只计算纯模型 forward”。

## 1.5 少样本/无样本启动与泛化

官方强调工业异常样本难以获得，系统需要在 few-shot 或 zero-shot 条件下快速部署。

官方允许或建议的方向包括：

- 迁移学习；
- 相关任务预训练；
- 合成数据；
- GAN 等缺陷模拟；
- 在线学习；
- 新环境快速适配。

比赛隐藏测试前的适配数据规模为：

- **100 张带标注的无缺陷图片或视频**
- **30 张有缺陷图片或视频**

随后在：

- **1000+ 张测试图片或视频**

上评测。

当前必须注意：

> 官方文档尚未明确 100 张正常和 30 张缺陷数据的“标注”粒度究竟是图像级标签、框、像素 mask、视频时间段标签，还是多种形式并存。不能提前假定一定提供 mask 或 bbox。

## 1.6 用户反馈驱动优化

当模型发生误检或漏检时，操作员可以反馈，例如标记漏检。

系统应支持：

- 回溯检测结果；
- 查看异常热力图或判定依据；
- 更新阈值、memory bank、prototype 或模型参数；
- 保留版本；
- 支持回滚；
- 避免一次错误反馈破坏已有模型。

官方举例包括强化学习或主动学习，但**不要求必须使用这些方法**。只要实现用户反馈后可验证的动态优化即可。

## 1.7 数据与泛化要求

官方要求：

1. 使用公开数据集训练或验证；
2. 自行验证泛化能力；
3. 推荐数据集：
   - DAGM 2007
   - MVTec AD
4. 项目中还可补充 MVTec AD 2 等更困难的新数据集，但不能因此忽略官方推荐数据集。

## 1.8 可解释性与文档要求

必须提交可解释性文档，系统阐述：

- 方案选型依据；
- 为什么选择当前算法；
- 数据与图片等证据；
- 公开数据集结果；
- 泛化验证；
- 推理时间；
- 模型使用方法；
- 异常结果解释。

可解释输出建议至少包括：

- 原图；
- 异常分数；
- OK / NG；
- 异常热力图；
- mask；
- bbox；
- 缺陷面积、位置和数量；
- 阈值；
- 最相似正常参考区域；
- 触发复核的原因。

## 1.9 官方提交内容

官方文档明确要求：

- 模型代码，用于非公开测试集评估；
- 模型使用说明文件；
- 方案与可解释性文档；
- 公开测试集或公开数据集实验结果；
- 鼓励使用小模型。

实际工程包建议包含：

```text

config
adapt/train script
image inference script
video inference script
model weights（若官方提交规则要求或允许）

README
```

注意：

> 原始赛题文档明确写了“模型代码”，但对是否必须随包提交预训练权重、是否允许评测环境联网下载、模型文件大小上限等信息没有完全说明，必须通过官方答疑确认。

# 3. 用户的固定原则

## 3.1 唯一优化目标

> **只最大化华为比赛最终得分。**

不追求：

- 论文发表；
- 学术创新；
- 自己发明网络；
- 模型一定最新；
- 结构一定优雅；
- 一定沿用医学图像分割经验；
- 一定使用 MedNeXt；
- 一定使用 YOLO；
- 一定使用某个基础模型。

## 3.2 允许优先复用

只要官方规则和许可证允许，可以优先使用：

- 官方 baseline；
- 排行榜高分代码；
- 作者公开权重；
- 预训练权重；
- 成熟开源库；
- 已验证的后处理；
- ONNX、TensorRT 等部署方案；
- 合法的模型融合与集成。

## 3.3 不做无收益工作

每项工作开始前必须回答：

```text
预计提高哪部分分数？
预计能提高多少？
需要多少时间？
失败风险多大？
是否影响速度和稳定性？
是否违反规则或许可证？
```

不能明确回答的工作暂缓。

## 3.4 得分优先顺序

在官方细则未进一步公布前，按下面顺序避免丢分：

1. **规则合规与可运行**
2. **方案完整度**
3. **专家评分所需的文档、演示和可解释性**
4. **速度**
5. **准确率**
6. **低成本的系统亮点**
7. **学术创新**

这不是说准确率不重要，而是准确率提升必须与最终总分权重、速度损失和工程成本一起计算。

## 3.5 代码组织原则

优先维护：

> **一个主代码库、一套配置系统、一套统一输入输出接口。**

不要默认建立三个互不相干的分类、YOLO、分割仓库。

理想情况下，从一张异常热力图得到：

```text
整图异常分数 → OK / NG
阈值化       → mask
连通区域     → bbox
统计         → 面积、数量、位置
```

只有当官方标签和评测明确要求时，再增加专用检测或分割分支。

# 6. 决策记录

## 2026-07-20：项目目标由“研究先进模型”改为“最终得分最大化”

**决定：**

- 允许优先复用规则允许的开源代码和权重；
- 不再以论文创新为主要目标；
- 模型选择以最终总分、速度、稳定性和工程成本为依据；
- 需要保留足够的适配、工程、解释和文档工作，以避免方案完整度和专家评分丢分。

**原因：**

- 竞赛最终评分中，准确率并非唯一部分；
- 方案完整度、速度和专家评分合计权重更高；
- 单纯追排行榜模型可能速度不合格、工程不完整或不适配隐藏数据。

## 一、先给结论

### 最值得参考的企业/工厂路线

1. **技术实现第一参考：NVIDIA 工业视觉质检流水线**
   - 原因：公开资料最完整，包含“未标注数据自监督适配 → 分类/检测/分割任务头 → 知识蒸馏 → DeepStream 部署”全流程。
   - 你可以直接模仿它的工程结构，而不是只模仿某个网络。
   - 官方资料：[Build a Real-Time Visual Inspection Pipeline with NVIDIA TAO 6 and DeepStream 8](https://developer.nvidia.com/blog/build-a-real-time-visual-inspection-pipeline-with-nvidia-tao-6-and-nvidia-deepstream-8/)

2. **真实超级工厂第一参考：TSMC 智能制造体系**
   - 原因：它不是只做图片缺陷检测，而是把视觉检测、设备故障检测、虚拟量测、工艺控制、良率分析、智能诊断和自学习组成完整系统。
   - 对你的启发：竞赛里的“方案完整度”不只是模型，而是适配、阈值、反馈、部署、日志和复现。

## 第一优先级：最贴近你的竞赛

### 2. SuperADD（CVPR 2026 VAND 工业赛道）

**重要程度：★★★★★**

- Training-free、class-agnostic。
- 使用 DINOv3 特征、正常样本 memory bank、重叠切块、亮度增强、memory-bank 子采样和形态学后处理。
- 特别针对 MVTec AD 2 的光照变化和分布偏移。
- 直接输出异常热力图，之后可以得到 mask、框和整图 OK/NG。

链接：

- [论文](https://arxiv.org/abs/2605.14808)
- [代码](https://github.com/LukasRoom/SuperADD)

**为什么适合你：**

```text
少量正常图
    ↓
提取 DINOv3 patch 特征
    ↓
构建正常 memory bank
    ↓
测试图与正常特征比较
    ↓
异常热力图
    ↓
mask / bbox / OK-NG
```

它比直接把 MedNeXt 搬过来更符合“未知缺陷＋少样本启动”。

---

### 3. SubspaceAD（CVPR 2026）

**重要程度：★★★★★**

- Training-free few-shot。
- 冻结 DINOv2 特征，用 PCA 建模正常特征的低维子空间。
- 推理时根据特征无法被正常子空间重建的残差判断异常。
- 结构简单，特别适合做你的第一个可靠 baseline。

链接：

- [论文](https://arxiv.org/abs/2602.23013)
- [代码](https://github.com/CLendering/SubspaceAD)
- [项目页面](https://clendering.github.io/SubspaceAD/)

**对你的价值：**

- 比复杂的多头网络更容易先跑通。
- PCA/子空间模型与你应用数学背景也比较契合。
- 可以研究 DINOv2、DINOv3、ConvNeXt 不同特征的效率—效果平衡。

---

### 4. FastRef（CVPR 2026）

**重要程度：★★★★☆**

- Few-shot industrial anomaly detection。
- 核心是利用测试图像统计信息，进一步修正有限正常样本形成的 prototype。
- 针对“少量正常图覆盖不了正常变化”的问题。

链接：

- [论文](https://arxiv.org/abs/2506.21398)
- [CVPR 2026 论文页面](https://openaccess.thecvf.com/content/CVPR2026/html/Li_FastRef_Fast_Prototype_Refinement_for_Few-shot_Industrial_Anomaly_Detection_CVPR_2026_paper.html)

**建议用途：**

- 不必一开始复现。
- 当 SubspaceAD/SuperADD 在正常外观变化较大时误报很多，再参考它做 prototype refinement。

## 第二优先级：解决零样本、逻辑异常和多产品统一模型

### 5. AnomalyVFM（CVPR 2026）

**重要程度：★★★★☆**

- 将纯视觉基础模型适配成 zero-shot anomaly detector。
- 目标是在目标产品没有训练图时也能检测和定位异常。
- 更适合作为前沿研究分支，不一定适合直接部署到 RTX 2060。

链接：

- [论文](https://openaccess.thecvf.com/content/CVPR2026/papers/Fucka_AnomalyVFM_--_Transforming_Vision_Foundation_Models_into_Zero-Shot_Anomaly_Detectors_CVPR_2026_paper.pdf)

**注意：**

---

### 6. UniVAD（CVPR 2025）

**重要程度：★★★★★**

- Training-free few-shot unified anomaly detection。
- 同时考虑工业异常、逻辑异常和医学异常。
- 使用部件/区域信息与关系建模，适合少件、错件、顺序错误、数量错误等问题。

链接：

- [论文](https://openaccess.thecvf.com/content/CVPR2025/html/Gu_UniVAD_A_Training-free_Unified_Model_for_Few-shot_Visual_Anomaly_Detection_CVPR_2025_paper.html)
- [代码](https://github.com/FantasticGNU/UniVAD)
- [项目页面](https://uni-vad.github.io/)

**它解决的不是单纯划痕，而是：**

```text
应该有 4 个零件，实际只有 3 个
零件都有，但位置或顺序错误
部件外观正常，但组合关系错误
```

这正好对应赛题里的缺件少件和逻辑错误。

**重要程度：★★★★☆**

链接：

链接：

## 四、你这个竞赛最推荐的技术路线

## 总原则

不要一开始写三个相互独立的代码库，也不要固定要求分类、YOLO、分割各有一个模型。

## 主线模型

```text
高分辨率图片
    ↓
切块或多尺度输入
    ↓
DINOv3 / DINOv2 / ConvNeXt 特征
    ↓
SubspaceAD 或 SuperADD 异常评分
    ↓
像素级异常热力图
    ↓
阈值＋形态学＋连通域
    ↓
同时得到：
1. image anomaly score
2. OK / NG 分类
3. anomaly mask
4. bounding boxes
5. 面积、数量、位置
```

### 这里不需要三个检测头

分类、分割和检测框可以从同一异常热力图得到：

```text
异常热力图最大值/Top-K均值 → 整图异常分数
异常热力图阈值化          → 分割 mask
mask 连通区域的极值坐标    → bbox
```

只有在比赛方提供了大量明确的框标签或像素标签时，才增加监督检测/分割 head。

## 少量缺陷数据怎么用

题目会给少量正常和缺陷样本进行迁移适配。建议分三层使用：

### 第 1 层：100 张正常图

- 建立正常 memory bank 或 PCA 子空间。
- 估计亮度、尺度、位置、纹理的正常变化范围。
- 做数据增强和阈值初步估计。

### 第 2 层：30 张缺陷图

- 不一定从头训练网络。
- 主要用于：
  - 选择阈值；
  - 调整不同区域权重；
  - 学习已知缺陷 prototype；
  - 训练一个很小的分类/分割头；
  - 校准漏检与误检代价。

### 第 3 层：用户反馈

- 将人工确认的正常误报加入正常参考库。
- 将漏检区域加入缺陷 prototype。
- 先做 memory/prototype 更新，不要每次都完整微调大模型。
- 保存版本和回滚能力。

## 六、MedNeXt、YOLO 与异常检测的最终定位

| 方法 | 最适合解决 | 对你的项目定位 |
|---|---|---|
| MedNeXt/UNet式分割 | 有足够像素级标签、要求精确边界 | 可做监督分割对照，不建议直接作为主线 |
| YOLO/RT-DETR | 有框标签、固定缺陷类别、多目标高速定位 | 适合少件、错件和已知缺陷，不解决未知缺陷 |
| SubspaceAD/SuperADD | 少量正常图、未知缺陷、像素级热力图 | 主线 |
| UniVAD/ObjectCore | 数量、顺序、组合关系错误 | 逻辑异常分支 |
| EfficientAD/轻量学生 | 实时部署 | 部署分支 |
| AnomalyVFM | 无目标域数据的零样本检测 | 前沿研究/教师模型 |

### 最适合你的最终组合

```text
SuperADD / SubspaceAD
        +
UniVAD 式逻辑关系
        +
EfficientAD / Tiny-Dinomaly 式轻量部署
        +
反馈更新 memory bank
```

不是：

```text
MedNeXt + YOLO + 分类器三个孤立模型
```

展开到最终总分：

| 项目 | 占最终总分 |
|---|---:|
| 方案完整度 | 30% |
| 答案准确率 | 12% |
| 检测时间 | 18% |
| 专家评分 | 40% |

因此：

> **隐藏测试准确率虽然重要，但它直接决定的最终总分只有约 12%。**

例如，准确率评分从 80 提升到 90，最终总分只增加：

```text
10 × 12% = 1.2 分
```

而：

```text
方案完整度提高 10 分 → 最终增加 3 分
专家评分提高 10 分   → 最终增加 4 分
```

所以不能只追求排行榜最高准确率，还必须同时优化：

- 能否一键运行；
- 是否支持少样本适配；
- 是否支持图片与视频；
- 是否满足 2500×2500、RTX 2060、200 ms 约束；
- 是否有异常热力图、mask、bbox 和 OK/NG；
- 是否支持用户反馈；
- 是否有完整代码、权重、配置、日志、说明和演示。

## 3. 得分优先级

### 第一优先级：不丢工程分

必须交付：

```text
代码
权重
配置文件
依赖清单
适配脚本
图片推理脚本
视频推理脚本
速度测试脚本
可解释结果
使用说明
实验报告
演示视频
```

优先保证：

- 一键运行；
- 不依赖手工改路径；
- 不出现环境冲突；
- 隐藏测试环境中可复现；
- 输入输出格式严格符合要求；
- 所有异常情况有日志和报错提示。

### 第二优先级：速度

检测时间占最终总分约 18%，必须单独作为核心指标优化。

重点测试：

```text
预处理时间
模型推理时间
后处理时间
总耗时
显存占用
适配时间
```

优先使用：

- FP16；
- ONNX；
- TensorRT；
- memory bank 子采样；
- 小 backbone；
- 重叠切块数量控制；
- 级联推理；
- 批处理；
- 视频帧抽样或时序缓存。

### 第三优先级：准确率

准确率提升采取“低风险、高收益”路线：

- 直接复现公开高分方法；
- 多模型候选实测；
- 自动阈值搜索；
- 正常样本与缺陷样本分别建模；
- 模型融合；
- 疑难样本二次复核；
- 在速度预算内使用测试时增强；
- 对不同产品类别采用不同阈值或 memory bank。

### 第四优先级：低成本专家分

不追求发表论文，只做容易展示的系统亮点：

1. **自动阈值校准**
2. **正常 reference bank 自动建立**
3. **用户反馈更新 memory bank**
4. **轻量模型与高精度模型动态级联**
5. **同一热力图生成分类、mask、bbox 和解释结果**
6. **图片/视频统一接口**
7. **模型版本管理与回滚**
8. **错误案例可视化和检测逻辑回溯**

这些内容实现成本低，却能显著提升方案完整度和专家观感。

## 4. 开源代码和权重的使用原则

### 可以优先复用

只要规则与许可证允许，优先使用：

- 官方公开 baseline；
- 排行榜高分代码；
- 论文作者公开权重；
- ImageNet、DINOv2、DINOv3 等预训练权重；
- Anomalib；
- ONNX / TensorRT；
- 公开部署示例；
- 数据增强和后处理库。

### 必须检查

每个外部项目都记录：

| 项目 | 必须确认 |
|---|---|
| 竞赛规则 | 是否允许外部预训练、公开权重和开源代码 |
| 软件许可证 | 是否允许修改、再发布和竞赛提交 |
| 权重许可证 | 权重是否有单独限制 |
| 数据许可证 | 是否允许训练与比赛用途 |
| 引用要求 | README 和报告中如何标注 |
| 商业/竞赛限制 | 是否禁止某些用途 |
| 可复现性 | 隐藏环境能否下载和运行 |

### 禁止的高风险做法

```text
下载冠军项目
直接使用原权重
只修改项目名称
不说明来源
无法解释代码
```

这种做法可能导致：

- 原创性审查风险；
- 许可证风险；
- 答辩失败；
- 隐藏测试环境无法运行；
- 专家评分极低；
- 取消成绩。

最合理的复用方式是：

```text
公开高分模型
    ↓
作为核心算法
    ↓
自己完成：
数据适配
阈值校准
高分辨率切块
速度优化
视频接口
反馈机制
工程封装
结果解释
文档与演示
```

|---|---:|---:|---:|---:|---:|---:|

| SubspaceAD | 实测 | 实测 | 实测 | 实测 | 实测 | 实测 |
| EfficientAD | 实测 | 实测 | 实测 | 实测 | 实测 | 实测 |
| Dinomaly | 实测 | 实测 | 实测 | 实测 | 实测 | 实测 |

选择规则：

```text
准确率高但过慢
    → 教师模型 / 疑难样本复核模型

速度快且效果稳定
    → 主推理模型

逻辑异常能力强
    → 专用补充分支

部署麻烦、收益很小
    → 舍弃
```

即使某个旧模型得分更高，也优先用旧模型；即使某个最新模型学术上更先进，但速度慢、复现困难，也舍弃。

## 6. 推荐的得分型系统结构

建议一个代码库，不做三个互相独立的项目。

```text
输入图片或视频
       ↓
产品区域检测 / 对齐 / 高分辨率切块
       ↓
轻量异常检测模型
       ↓
明显正常 ─────→ 直接通过
明显异常 ─────→ 直接拦截
不确定样本
       ↓
高精度模型二次判断
       ↓
异常热力图
       ↓
自动阈值 + 形态学 + 连通域
       ↓
输出：
OK / NG
异常分数
异常 mask
异常 bbox
面积、数量、位置
解释图
```

这种级联结构的好处：

- 大多数简单样本只运行快模型；
- 少数难样本才运行强模型；
- 平均速度较低；
- 准确率可以保持；
- 方案完整度高；
- 专家答辩时容易讲清楚；
- 可以包装成“动态路由”或“自适应复核”。

## 8. 决策原则

后续任何新想法，都用下面五个问题判断：

1. **能否提高最终总分？**
2. **提高的是准确率、速度、完整度还是专家评分？**
3. **预计能提高多少分？**
4. **实现和调试需要多少时间？**
5. **是否存在规则、许可证或复现风险？**

不满足以下条件的工作直接舍弃：

```text
预期得分收益明显
        且
实现风险可控
        且
能在截止日期前稳定完成
```
