#### 实验设计与数据集划分说明

##### 一、数据集划分（固定 7:1:2，seed=42）

数据来源：LiTS 内部数据集，共 **131 cases**。

| 子集 | 数量 | 用途 | 是否影响模型 |

| train | 92 | 梯度更新、权重学习 | 是 |
| val   | 13 | 训练过程监控、checkpoint_best 选择 | 是（间接） |

##### 数据混合与二阶段训练的硬性原则（2026-07-11）

后续所有 Dataset003_Liver、Dataset013_HCCReferencedCT、MSD/HCC 混合训练、Adapter/LoRA、蒸馏、replay 或串联微调实验，统一遵守以下隔离规则：

1. **只能混合各数据集的 train split**。Dataset003_Liver 只允许使用 92 个 train cases；Dataset013_HCCReferencedCT 只允许使用 70 个 train cases。
2. **val split 只用于训练监控和 checkpoint 选择**，不能进入梯度更新、replay buffer、蒸馏教师样本池或 adapter 训练样本池。
3. **test split 只用于最终报告**，不能用于调参、挑模型、阈值选择、失败案例筛选后重训，也不能混入任何阶段的训练。
4. 若做 HCC adapter：Dataset003/IRCADb 推理默认不开启 HCC adapter，HCCReferencedCT 推理开启 HCC adapter；adapter 的训练样本仍只来自 HCC train 70 cases。
5. 若提升或重建 split 文件，`splits_final.json` 是 nnU-Net 实际读取的 train/val 文件；配套 `split_info*.json` 必须记录 held-out test cases。旧 active 文件必须先备份，再切换。

当前 HCCReferencedCT active split 为 `701020_stratified_v2`：`splits_final.json` 记录 70 train + 10 val，`split_info_701020_stratified_v2.json` 记录同一划分的 21 test cases。

##### 二、为什么不用 val 指标做实验对比

`checkpoint_best.pth` 是根据 val loss 选出的，val set 间接参与了模型选择。
用 val 指标横向比较各实验，相当于在"选手打过的题"上评分，存在数据泄露风险。

**唯一可信的对比数字来源：`test_report_custom.txt`（26-case test set）。**

##### 三、Pipeline 设计原则

###### 训练结束后自动触发的流程

```
perform_actual_validation()
  │
  ├─ [nnUNet 内部] 在 val 13 cases 上推理 → validation/summary.json
  │                                          用于 checkpoint 选择记录
  │
  └─ [AutoInternalTestMixin] 在 test 26 cases 上推理
       ├─ test_prediction/   （推理完自动删除 nii.gz，节省磁盘）
       ├─ test_report_custom.txt   ← 实验对比的唯一数字来源
       └─ test_viz/                ← TP/FP/FN 可视化（纯 CT 对照 + 叠加图）
```

###### 刻意不生成的内容

| 产物 | 废弃原因 |
|------|---------|
| `report_custom.txt` | val 13 cases 参与了 ckpt 选择，对比有泄露嫌疑 |
| `val_viz/` | val 和 test 完全不重叠，val 图没有分析价值 |
| `vis_png_custom/` | 旧风格冗余，被 test_viz 取代 |

##### 七、为什么 MedNeXt 最强

###### 核心原因：大卷积核带来更大感受野

标准 nnUNet 用 3×3×3 卷积，每个体素只能"看到"周围 3 个体素的信息。
MedNeXt 用**深度可分离大卷积核**（最大到 7×7×7），感受野直接扩大 8 倍以上。

对肝脏肿瘤分割的意义：
- 肿瘤边界模糊，需要参考更大范围的上下文才能判断是否是肿瘤
- 大核让模型在每个体素处就能"看到"更远的周边组织，判断更准确

###### ConvNeXt 设计带来的工程优势

MedNeXt 把自然图像领域验证过的 ConvNeXt 架构适配到 3D 医学图像：

| 设计 | 作用 |
|------|------|
| 倒置瓶颈（先升维再大核卷积） | 在高维特征空间用大核，表达能力更强 |
| LayerNorm 替代 BatchNorm | 小 batch size 下更稳定（3D 医学图像显存限制 batch 很小） |
| GELU 激活函数 | 梯度更平滑，训练更稳定 |
| 深度可分离卷积 | 大核下参数量可控，不会过拟合 |

###### 对比 MLAUNet 系列

MLAUNet 加了 Attention 机制，理论上也能捕获全局关系，但：
- Attention 是在特征图层面做全局加权，计算开销大，实际能用的分辨率受限
- MedNeXt 的大核卷积在**局部大范围**内效果更直接，且计算效率更高
- MLAUNet_MoE_V4 加了混合专家（MoE）后提升到 0.8330，接近 MedNeXt 但仍有差距

###### 对比 SizeOversample 系列

SizeOversample 只改了数据采样策略（多采小肿瘤），骨干网络还是标准 nnUNet。
极小肿瘤 Dice 只比 Baseline 高 0.02 左右，骨干网络的特征提取能力才是关键瓶颈。

##### 二、Mixin 功能速查

> 所有 Trainer 均由基类 `nnUNetTrainer` + 若干 Mixin 组合而成，实现在 `pumengyu/mixins.py`

| Mixin | 作用层面 | 核心机制 | 关键超参 |
|---|---|---|---|
| `SizeStratifiedOversampleMixin` | 数据采样 | 按肿瘤体素数百分位分层，不同大小 case 重复不同次数；边界从当前 fold 训练集自动算，无硬编码阈值 | `SSO_TINY_PCTL=20`, `SSO_SMALL_PCTL=45`, `SSO_HUGE_PCTL=90` 及各分层重复次数 |
| `NoMirrorMixin` | 数据增强 | 关闭训练和推理时所有轴的镜像增强；动机：肝脏右侧不对称，左右镜像产生解剖噪音 | 无 |
| `TumorOnlyTrainMixin` | 数据采样 | 从训练集剔除所有无肿瘤 case，验证集不变；故意让模型从未见"应全黑"输入 | 无 |
| `ExternalNoTumorMixin` | 数据采样 | 向训练集追加 25 个外部无肿瘤 case（CHAOS CT×20 + IRCADb×5），不修改 splits_final.json | `EXT_CASES` 列表 |
| `UnifiedFocalLossMixin` | Loss | CE+Dice 之上叠加 AsymmetricUnifiedFocalLoss（肿瘤类二值化），惩罚漏检 | `UFL_LAMBDA=0.5`, `UFL_DELTA=0.5`, `UFL_GAMMA=0.2` |
| `TverskyLossMixin` | Loss | 叠加 AsymmetricFocalTverskyLoss（delta=0.7），FN 惩罚是 FP 的 2.3 倍 | `TVL_DELTA=0.7`, `TVL_GAMMA=0.75`, `TVL_LAMBDA=1.0` |

## 显式结构复现鲁棒性实验


#### 显式结构复现鲁棒性实验

> 更新：2026-07-02  
> 新 Trainer：`nnUNetTrainer_DeepDWIBMedConfig`

---

##### 1. 核心问题

本实验不是为了简单证明 DW+IB 有效，而是回答一个更细的问题：

> MedNeXt 的性能是否可以由论文/结构图中显式公开的信息独立复现？

换句话说，我们想区分两类贡献：

1. **显式结构范式**：通道数、block 数、expansion ratio、DW conv、inverted bottleneck、encoder-decoder 层级。
2. **隐性实现细节**：官方代码里的 block 内部顺序、up/down 细节、padding、normalization group 数、skip 处理、deep supervision 输出等。

如果只对齐显式结构信息、不复用官方 MedNeXt 代码，也能接近 MedNeXt，说明该方法鲁棒，核心贡献主要来自公开可复现的结构范式。

如果仍明显低于 MedNeXt，说明 MedNeXt 的性能不仅来自结构图，还依赖代码级微观实现细节。

---

##### 2. 已有结果

| 模型 | 参数量 | 内部 Overall | 外部 Overall | 解释 |
|---|---:|---:|---:|---|
| DeepPlainResGN | ~61M | 0.7966 | 0.7442 | 深度 + 残差 + GN 不够 |
| DeepDWIBResGN | 58.12M | 0.8198 | 0.7886 | DW+IB 明显有效，但未复现 MedNeXt |
| MedNeXt-L | 61.78M | 0.8402 | 0.7705 | 官方/移植 MedNeXt-L |
| MedNeXt_MLA | — | 0.8259 | 0.8079 | 当前外部最优 |

`DeepDWIBResGN` 已经证明 DW+IB 是有效成分，但它没有对齐 decoder 的 block 组织和每层 expansion ratio，因此还不能回答“显式结构参数对齐后能否复现 MedNeXt”。

---

##### 3. 新实验：DeepDWIBMedConfig

`nnUNetTrainer_DeepDWIBMedConfig` 对齐 MedNeXt-L 中显式可见的结构配置，但保持自写实现。

###### 显式对齐项

| 项 | 配置 |
|---|---|
| channels | `32,64,128,256,512,256,128,64,32` |
| block_counts | `[3,4,8,8,8,8,8,4,3]` |
| expansion ratio | `[3,4,8,8,8,8,8,4,3]` |
| kernel size | `3` |
| block type | DW conv + inverted bottleneck + residual |
| skip fusion | add |
| deep supervision | `[full, 1/2, 1/4, 1/8, 1/16]` |

###### 刻意不对齐项

这些属于论文图外部更难无歧义复现的代码级细节：

| 项 | 本实验处理 |
|---|---|
| 官方 MedNeXt 类 | 不复用 |
| up/down block 细节 | 用自写常规实现 |
| ConvTranspose 后 padding 细节 | 不照搬官方特殊 padding |
| GroupNorm 细节 | 使用 `GroupNorm(8)`，不照搬官方 `num_groups=in_channels` |
| conv bias / 初始化 | 使用自写默认 |
| checkpoint 包装方式 | 使用本项目现有写法 |

---

##### 4. 模型参数量

实际参数量：

| 模型 | 参数量 |
|---|---:|
| MedNeXt-L | 61,782,192 |
| DeepDWIBResGN | 58,119,948 |
| DeepDWIBMedConfig | 62,571,919 |

`DeepDWIBMedConfig` 与 MedNeXt-L 只差约 1.3%，适合作为参数量近似对齐的独立复现实验。

---

##### 5. 判定标准

| 结果 | 解释 |
|---|---|
| 接近 MedNeXt-L 内部 0.8402 | 显式结构信息足以复现主要性能，MedNeXt-like DW+IB 设计鲁棒 |
| 明显高于 DeepDWIBResGN 0.8198，但低于 MedNeXt | block_counts/exp_r 等显式超参数很重要，但仍有代码细节贡献 |
| 接近 DeepDWIBResGN 0.8198 | 对齐显式配置收益有限，性能主要依赖更微观实现或官方结构细节 |

推荐论文表述：

> We construct an explicit-configuration MedNeXt-like model by aligning the publicly visible architectural hyperparameters, including channel widths, block counts, expansion ratios, and encoder-decoder hierarchy, while keeping the implementation independent from the official MedNeXt code. This evaluates whether MedNeXt-level performance can be recovered from the explicit architecture alone.

中文表述：

> 我们构建了一个显式结构参数对齐的 MedNeXt-like 模型，对齐通道数、block 数、expansion ratio 和 encoder-decoder 层级，但不复用官方 MedNeXt 代码，也不一比一复刻 block 内部实现细节。该实验用于检验 MedNeXt 的性能是否可以由公开可见的结构设计独立复现。
