##### 核心主线

**所有创新本质上都在做同一件事**：

> 在固定计算预算下，把省出来的空间用在更有价值的地方（更大感受野 / 更深网络 / 更多参数 / 更高效路由）

---

##### MLA（Multi-head Latent Attention，DeepSeek-V2）

**包装说法**：低秩 KV 压缩，高效长序列建模

**真正做了什么**：

标准 Attention 的 KV Cache 是瓶颈：每个 token 要存 K 和 V，序列长了显存爆炸。

MLA 把 K、V 先压缩到低维潜变量 c（d_c = d/4），推理时只存 c，需要时再解压：

```
标准：存 K[N, d] + V[N, d]       → 显存 O(N·d)
MLA：存 c[N, d_c]，d_c = d/4    → 显存 O(N·d/4)
推理时：K = W_K · c，V = W_V · c
```

**核心**：用一次低秩线性映射，把 KV 显存压缩 4 倍，长序列推理成本降到可接受范围。

**省出来的额度用在**：支持更长上下文，或更大 batch size。

##### Depthwise Separable Conv（MobileNet / MedNeXt）

**包装说法**（MedNeXt）：借鉴 ConvNeXt 架构，对齐 Transformer 设计哲学

**真正做了什么**：

标准卷积参数是 $k^3 \times C^2$，k 和 C 同时大就爆炸。解耦空间混合和通道混合：

```
Depthwise k×k×k：只做空间混合，参数 k³C（无 C² 项）
Pointwise 1×1×1：只做通道混合，参数 C²（无 k³ 项）
合计：k³C + C²
```

C 够大时（C ≥ 19），$k^3C + C^2 < 27C^2$（标准 3×3×3），**参数更少，感受野更大**。

**核心**：把参数中的 $k^3 \times C^2$ 拆成 $k^3C + C^2$，消掉耦合项，参数省出来支撑更大的核。

**省出来的额度用在**：核从 3 扩到 7（甚至更大），感受野成三次方增长。

**MedNeXt 的真实贡献**：把这个操作从 2D 搬到 3D 医学图像，验证大核在体积分割任务上同样有效。LN/GELU 是 ResNet 现代化的工程细节，和 Transformer 无本质关联。

##### MoE（Mixture of Experts）

###### 第一层：基础 MoE（早就有，不是 DeepSeek 的创新）

**真正做了什么**：

N 个 expert（每个就是一个 FFN），router 是一个线性层，简单粗暴地为每个 token 选 Top-K：

```
router = nn.Linear(d_model, N, bias=False)   ← 就一个线性层

每个 token：
  scores = router(token)          → N 维 logits
  topk_idx = scores.topk(K)      → 选 Top-K 个 expert
  只走这 K 个，其余 N-K 个不激活

计算量 = K 个 expert
参数量 = N 个 expert
```

**核心**：计算量和参数量解耦，参数堆 N 个，每次只算 K 个。

---

###### 第二层：共享 Expert（DeepSeek MoE 的真实创新）

**问题**：基础 MoE 里每个路由 expert 既要学通用知识又要学专化知识，互相干扰，需要更多 expert 才够用。

**做了什么**：加 1~2 个共享 expert，所有 token 必走，专门学通用知识；路由 expert 只需专注各自细分方向：

```
输出 = shared_expert(x) + Σ gate_k · routed_expert_k(x)
         ↑ 所有 token 必走      ↑ router 选 Top-K 个
```

你的代码实现（`mla_unetr.py:185`）：
```python
out = (self.shared_expert(x_flat) + routed).reshape(B, N, D)
```

**节省在哪里**：共享 expert 把通用知识兜底，路由 expert 专化效率更高，**更少的路由 expert 可以达到标准 MoE 更多 expert 的同等效果**。不是降低单次计算量，是提升了 expert 容量利用率。

**额外细节（loss-free bias 负载均衡）**：
router 容易总选同几个 expert（负载不均）。DeepSeek V3 用 EMA 统计各 expert 被选频率，自动调 bias 抑制过热 expert、激励冷门 expert，不加辅助 loss，梯度路径更干净。你的代码里 `update_expert_bias()` 就是这个。
