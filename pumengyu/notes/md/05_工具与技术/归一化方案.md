# 归一化方案分析：BN / IN / LN


#### 归一化方案分析：BN / IN / LN

> 针对当前项目（3D 肝脏肿瘤分割）各方法实际使用的 norm 做系统梳理

---

##### 1. 三种 Norm 的维度操作对比

输入 tensor 形状：`[B, C, D, H, W]`

```
BatchNorm3d (BN)
  归一化维度：[B, D, H, W]  → 每个 C 独立一套 (μ, σ)
  共 C 个统计量
  问题：B 小时 μ/σ 估计不准

InstanceNorm3d (IN)
  归一化维度：[D, H, W]     → 每个 (B, C) 独立一套 (μ, σ)
  共 B×C 个统计量
  特点：每个样本每个通道完全独立，不依赖 batch

LayerNorm (LN)
  归一化维度：[C, D, H, W]  → 每个 B 独立一套 (μ, σ)
  共 B 个统计量
  特点：每个样本内所有通道一起算，通道间会互相影响
```

| | BN | IN | LN |
|--|--|--|--|
| 归一化的维度 | B, D, H, W | D, H, W | C, D, H, W |
| 统计量数量 | C 个 | B×C 个 | B 个 |
| 不依赖 batch size | ❌ | ✅ | ✅ |
| 通道间是否互相影响 | 否（各通道独立） | 否（各通道独立） | 是（混在一起算） |

---

##### 2. 当前项目各方法实际使用的 Norm

###### MLAUNet（你的模型）

**两套 norm 并存**：

| 模块 | Norm | 来源 |
|------|------|------|
| Encoder / Decoder（卷积部分） | `InstanceNorm3d` | 从 nnUNetPlans.json 读取，随 nnUNet 框架 |
| MLA Bottleneck（Attention 部分） | `LayerNorm` | 写死在 `mla_unetr.py`，对齐 Transformer |

**plans 中的实际配置**（`nnUNetPlans.json`）：
```json
"norm_op": "torch.nn.modules.instancenorm.InstanceNorm3d",
"norm_op_kwargs": {"eps": 1e-05, "affine": true}
```

卷积 encoder/decoder 用 IN，bottleneck 的 MLA block 用 LN，这是合理的——各自对齐各自的技术路线。

---

###### nnUNet Baseline

全程 `InstanceNorm3d`，由 `get_matching_instancenorm` 自动根据 conv_op（Conv3d）选择。

---

###### MedNeXt-L

全程 `LayerNorm`（3D 适配版），ConvNeXt block 内每个位置都是 LN。

原因：MedNeXt 的设计目标是对齐 ConvNeXt/Transformer 训练配方，LN 在大模型训练中更稳定。

---

###### SwinUNETR-B

全程 `LayerNorm`，Swin Transformer 系列从设计之初就用 LN。

---

###### nnFormer

`LayerNorm`，同 Transformer 系列。

---

##### 3. 为什么 3D 医学图像分割主流用 IN 而不是 BN？

3D patch 体积大（如 128×128×128），GPU 显存限制下 batch size 通常只有 2~4。

BN 在 batch 上求统计量：

```
B=2 时，μ_c 只由 2 个样本的 D×H×W 个点决定
→ 样本间差异大（不同病人肿瘤大小、位置完全不同）
→ μ/σ 估计方差极大，归一化不稳定
```

IN 在单个样本单个通道的空间维度上求统计量，完全不受 batch size 影响。

---

##### 4. 为什么 Transformer 用 LN 而不是 IN？

Transformer 的输入是序列 `[B, N, C]`（N 是 token 数，没有空间 D/H/W），IN 对空间维度归一化，**在序列上没有对应的操作**，不适用。

LN 对每个 token 的所有特征维度 C 归一化，天然匹配序列结构。

你的 MLA bottleneck 把 3D feature map 展平成 token 序列再做 attention，所以用 LN 是对的。

---

##### 5. 结论

| 结论 | 说明 |
|------|------|
| 你的卷积部分用 IN | 正确，和 nnUNet baseline 一致，公平对比 |
| 你的 MLA 部分用 LN | 正确，Transformer 结构的标准选择 |
| MedNeXt 全用 LN | 工程选择，对齐 ConvNeXt 训练配方，不代表 LN > IN |
| 3D 医学图像 BN 基本不用 | batch size 太小，BN 失效 |

当前的混合 norm 方案（卷积→IN，attention→LN）是最自然的选择，无需修改。
