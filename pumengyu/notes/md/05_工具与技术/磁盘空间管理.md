## 大目录迁移到 HDD（软链接方案）

```bash
# 迁移（有进度，支持断点续传）
rsync -ah --progress /nvme/data/ /hdd/data/

# 确认大小一致后删源目录，建软链接
rm -rf /nvme/data
ln -s /hdd/data /nvme/data

# 验证
ls -la /nvme/data   # 应显示 -> /hdd/data
```

**注意**：软链接本身零开销，但 HDD 读速 ~150 MB/s vs NVMe ~3000 MB/s，
训练数据放 HDD 会导致 GPU 等数据（利用率 0%）。训练用数据尽量放 NVMe。

## 两阶段框架空间占用全景

```
stage1_softmax/   114G   Stage1对131个case的推理输出（3通道npz，原始CT空间）
s2feat/            42G   旧方案：裁剪+重采样后的缓存（已废弃）
stage1_prob/        8G   新方案：仅肿瘤通道 float16 b2nd（load_case现算裁剪+重采样）
```

### 优化方案（2026-06）

**问题**：s2feat 42G + stage1_softmax 114G = 156G，且 s2feat 放 HDD 导致训练卡 I/O。

**方案**：消灭 s2feat，改为 load_case 现算；stage1_softmax 压缩为 float16 b2nd（stage1_prob/）。

- `_prepare_s2_features()`：读 npz 肿瘤通道 → float16 b2nd → `stage1_prob/`（~8G）
- `Stage2_nnUNetDatasetBlosc2.load_case()`：读 stage1_prob b2nd → 内存裁剪+重采样 → 喂网络
- 训练完成后可删 stage1_softmax（114G），只保留 stage1_prob（8G）永久存档

**最终占用**：8G（vs 原来 156G），节省 148G。

## s2feat / stage1_softmax 父子关系

```
stage1_softmax/*.npz  ──→  _prepare_s2_features()  ──→  stage1_prob/*.b2nd
（可删，训练完后）                                        （保留，调参复用）
```

- 只要 stage1_prob 在，Stage2 随时可重训，不需要重新跑 Stage1 推理
- stage1_softmax 可在 stage1_prob 生成完毕、训练确认正常后删除

## 进程管理备忘

```bash
pgrep -a mihomo          # 查看 mihomo 进程（含命令行）
pkill -x mihomo          # 按精确名字杀所有同名进程
ps aux | grep 进程名      # 查看进程详情（CPU/MEM）
```

**坑**：`.bashrc` 里用 `pgrep -x` 检测进程名必须与二进制文件名完全一致，
否则每次开终端都会多启动一个进程（如 `mihomo-linux-am` ≠ `mihomo`）。
