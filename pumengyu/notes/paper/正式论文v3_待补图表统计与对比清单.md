## 1. 当前决定

1. 正式论文继续以 `MedNeXt_MLA_MoE` 为主要介绍模型。
2. 主模型的价值不是三个数据域统一排名第一，而是：
   - 保留 MedNeXt-L 强局部卷积骨干；
   - 在最低分辨率 bottleneck 引入 MLA-style 低秩 K/V 全局交互；
   - 通过 MoE-FFN 完成条件特征变换；
   - 在 3D-IRCADb 上取得当前最高 Overall 和 Tumor Dice，并将无肿瘤误报病例由 MedNeXt 的 3/5 降至 2/5；
   - 完成 MHA/MLA × MLP/MoE 的严格 2×2 三域对照，同时如实呈现 HCC 上的域依赖性。
3. `EfficientMedNeXt_L_Official` 只保留为官方架构基线，不作为论文主角，也不再围绕它扩展新模型。
4. 不制作以 EfficientMedNeXt 为中心的“效率—可靠性图”。如需报告效率，只做围绕主模型及严格结构对照的复杂度表。
5. 当前投稿前不新增 GAN、MAE、EfficientMedNeXt_MLA 等新训练线。

## 3. P0：三组病例级配对统计

### 3.1 固定比较

#### 对比一：完整组合相对原始骨干

```text
MedNeXt_MLA_MoE vs MedNeXt
```

回答：

- 完整 bottleneck 组合相对原始 MedNeXt 改变了哪些病例；
- IRCADb 上的平均提升是否由多数病例共同贡献，还是由少数病例拉动；
- HCC 上是否存在收益反转；
- 无肿瘤误报从 3/5 降到 2/5 对应的是哪些病例。

#### 对比二：固定 MoE，比较 MHA 与 MLA

```text
MedNeXt_MLA_MoE vs MedNeXt_MHA_MoE
```

回答：

- 在相同 MoE-FFN 下，低秩 K/V 路径与标准 MHA 的病例级差异；
- 三域小幅 Overall 差异是否在病例层面方向一致；
- 不能仅凭平均值把 MLA 描述为统一优于 MHA。

#### 对比三：固定 MLA，比较 MLP 与 MoE

```text
MedNeXt_MLA_MoE vs MedNeXt_MLA
```

回答：

- MoE 在 MLA 路径下对 Internal、IRCADb 和 HCC 的影响；
- 为什么 IRCADb 提升而 HCC 下降；
- 哪些病例从 MoE 中获益，哪些病例发生漏检或退化。

### 3.2 主要与次要终点

主要终点：

```text
GT 阳性病例上的 Tumor Dice
```

次要终点：

- Tumor Recall；
- Tumor Precision；
- all-case Liver Dice；
- 每个数据域的病例级 Overall（仅作补充）；
- 严重失败数；
- 完全漏检数；
- 无肿瘤病例的 case-level FP 计数。

不同数据域分别计算，不对 Internal、IRCADb 和 HCC 合并检验，也不计算跨数据集平均。

### 3.3 统计方法

每个数据域、每组对比采用相同病例的配对结果：

```text
paired difference = MedNeXt_MLA_MoE - comparator
```

至少报告：

1. 两种方法各自的均值、中位数和四分位距；
2. 病例级配对差值的均值与中位数；
3. 配对 bootstrap 95% 置信区间；
4. 双侧 Wilcoxon signed-rank 检验；
5. 同一指标、同一数据域内三组比较使用 Holm 校正；
6. 明确有效病例数和排除原因。

推荐默认参数：

```text
bootstrap repetitions = 10,000
confidence level = 95%
random seed = 固定并写入结果
```

### 3.4 统计解释边界

- Internal 肿瘤阳性病例为 23 例，IRCADb 肿瘤阳性病例为 15 例，HCC test 为 21 例且全部阳性。
- Internal 仅 3 个阴性病例，IRCADb 仅 5 个阴性病例。FP 结果以 `x/n` 和具体病例清单报告，不把小样本 McNemar p 值包装成强证据。
- case-level 配对检验只能说明固定 checkpoint 在固定病例上的差异，不能替代多随机种子或多 fold 训练。
- 若 95% CI 跨 0 或校正后不显著，仍可报告效应方向和病例分布，但不能写“显著优于”。
- 统计检验结果不能改变已经观察到的域依赖性：IRCADb 的收益不能外推为 HCC 的统一收益。

## 5. P1：主模型复杂度与实际运行代价表

### 5.1 比较范围

只比较论文机制相关方法：

```text
MedNeXt
MedNeXt_MHA
MedNeXt_MLA
MedNeXt_MHA_MoE
MedNeXt_MLA_MoE
```

可将 EfficientMedNeXt-L 作为表末的参考基线，但不参与 MLA/MoE 贡献归因。

### 5.2 需要报告的项目

- 总参数量；
- attention 子模块参数量；
- FLOPs 或 MACs，输入固定为 `1×1×128×128×128`；
- 单 patch 前向时间；
- 单个固定体数据的端到端推理时间；
- 推理峰值显存；
- 如条件允许，再报告训练 step 时间和训练峰值显存。

### 5.3 公平 benchmark 条件

所有模型必须：

- 使用同一张 GPU；
- 同一 CUDA/PyTorch 环境；
- 同一输入 patch；
- 同一 batch size；
- 同一 deep-supervision 开关；
- 同一 AMP 设置；
- 同一 `torch.compile` 设置；
- warm-up 后重复多次；
- 报告均值、标准差和重复次数；
- benchmark 时无其他 GPU 进程干扰。

历史训练日志不能直接作为正式复杂度表，因为模型可能使用不同 GPU 数、不同编译设置和不同系统负载。

### 5.4 EfficientMedNeXt 的记录边界

已经确认：

- 参数量约为 2.19M；
- 用户实际训练时因单 GPU 过慢而改为双 GPU 续跑；
- 单 GPU 初期常见 epoch 时间约 307—308 秒，部分时段达到约 488—612 秒；
- 当前主模型在启用 `torch.compile` 后常见 epoch 时间约 148 秒；
- EfficientMedNeXt 的 HCC Tumor Dice/Recall 为 0.3468/0.2697，低于 MedNeXt 的 0.4175/0.3582；
- EfficientMedNeXt 的低参数量没有在当前官方实现中转化为实际训练速度优势。

尚不能写入具体数值的内容：

- EfficientMedNeXt 峰值显存为多少 GB；
- 它比主模型多占多少显存；
- 严格同条件下的训练吞吐差值。

原因：现有日志没有保存峰值显存数字。用户对其高显存占用有明确运行记忆，可作为内部 benchmark 动机，但论文正式数字必须重新测量。

正式写作建议：

> EfficientMedNeXt-L substantially reduced the parameter count, but its official implementation did not yield a corresponding wall-clock training advantage in our pipeline. Because historical runs used different compilation and multi-GPU settings, standardized runtime and memory measurements are reported separately when available.

若不做统一 benchmark，则正文只保留参数量和性能，不写实际速度/显存强结论。

## 10. 推荐执行顺序

### 第一阶段：不运行 GPU

1. 收集三组对比在三个数据域的 per-case 指标；
2. 完成配对 bootstrap、Wilcoxon 和 Holm 校正；
3. 生成图 A、图 B；
4. 核对并合并现有病例图；
5. 补充 `ircadb_016` 主模型与 MedNeXt 直接比较；
6. 把结果回填正式主稿。

### 第二阶段：短时统一 benchmark

1. 固定同一张 GPU 和无干扰环境；
2. 对五个 MedNeXt 核心结构测参数、FLOPs、前向时间和峰值显存；
3. 如需保留 EfficientMedNeXt，再以相同条件测量；
4. 形成复杂度表，不重新训练模型。

### 第三阶段：可解释性补充

1. 为已有 checkpoint 增加只读 feature/attention hook；
2. 先验证加入 hook 前后预测逐元素一致；
3. 对固定病例提取统一图版；
4. 只有结果稳定且可解释时才进入正文。

### 第四阶段：投稿终审

1. 检查所有结果是否来自正式 case 清单；
2. 检查 checkpoint、trainer、dataset、fold 和 source-only/adapted 来源；
3. 检查图表数字与报告一致；
4. 检查 HCC FP rate 始终写为 N/A；
5. 检查无任何“内部最优”“三域统一提升”或“显著节省显存”等越界表述；
6. 完成摘要、结果、讨论和结论的最终同步。
