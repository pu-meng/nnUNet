## 1. 当前决定

1. 正式论文以 `MedNeXt_MLA_MoE` 为主模型，围绕其结构设计、严格控制变量消融、跨数据集表现与病例级失败模式展开分析。
2. 现有证据不支持主模型在三个数据域统一占优；其研究价值主要体现在：
   - 保留 MedNeXt-L 强局部卷积骨干；
   - 在最低分辨率 bottleneck 引入 MLA-style 低秩 K/V 全局交互；
   - 通过 MoE-FFN 完成条件特征变换；
   - 在 3D-IRCADb 上取得当前最高 Overall 和 Tumor Dice，并将无肿瘤误报病例由 MedNeXt 的 3/5 降至 2/5；
   - 完成 MHA/MLA × MLP/MoE 的严格 2×2 三域对照，同时如实呈现 HCC 上的域依赖性。
3. `EfficientMedNeXt_L_Official` 只保留为官方架构基线，不作为论文主角，也不再围绕它扩展新模型。
4. 不制作以 EfficientMedNeXt 为中心的“效率—可靠性图”。如需报告效率，只做围绕主模型及严格结构对照的复杂度表。
5. 当前投稿前不新增 GAN、MAE、EfficientMedNeXt_MLA 等新训练线。

### 3.3 统计方法

每个数据域、每组对比采用相同病例的配对结果：

```text
paired difference = MedNeXt_MLA_MoE - comparator
```

至少报告：

1. 两种方法各自的均值、中位数和四分位距；
2. 病例级配对差值的均值与中位数；
3. 配对重采样（paired bootstrap）95% 置信区间；
4. 双侧 Wilcoxon signed-rank 检验；
5. 同一指标、同一数据域内三组比较使用 Holm 校正；
6. 明确有效病例数和排除原因。

推荐默认参数：

```text
bootstrap repetitions = 10,000
confidence level = 95%
random seed = 固定并写入结果
```

### 3.4 统计解释边界

- MSD 肿瘤阳性病例为 23 例，IRCADb 肿瘤阳性病例为 15 例，HCC test 为 21 例且全部阳性。

- case-level 配对检验只能说明固定 checkpoint 在固定病例上的差异，不能替代多随机种子或多 fold 训练。
- 若 95% CI 跨 0 或校正后不显著，仍可报告效应方向和病例分布，但不能写“显著优于”。
- 统计检验结果不能改变已经观察到的域依赖性：IRCADb 的收益不能外推为 HCC 的统一收益。

## 5. P1：主模型复杂度与实际运行代价表

### 5.1 比较范围

只比较论文机制相关方法：


### 5.2 需要报告的项目

- 总参数量；
- attention 子模块参数量；
- FLOPs 或 MACs，输入固定为 `1×1×128×128×128`；
- 单 patch 前向时间；
- 单个固定体数据的端到端推理时间；
- 推理峰值显存；
- 如条件允许，再报告训练 step 时间和训练峰值显存。

### 5.3 公平 benchmark 条件

所有模型必须：

- 使用同一张 GPU；
- 同一 CUDA/PyTorch 环境；
- 同一输入 patch；
- 同一 batch size；
- 同一 deep-supervision 开关；
- 同一 AMP 设置；
- 同一 `torch.compile` 设置；
- warm-up 后重复多次；
- 报告均值、标准差和重复次数；
- benchmark 时无其他 GPU 进程干扰。

历史训练日志不能直接作为正式复杂度表，因为模型可能使用不同 GPU 数、不同编译设置和不同系统负载。

### 5.4 EfficientMedNeXt 的记录边界

已经确认：

- 参数量约为 2.19M；
- 用户实际训练时因单 GPU 过慢而改为双 GPU 续跑；
- 单 GPU 初期常见 epoch 时间约 307—308 秒，部分时段达到约 488—612 秒；
- 当前主模型在启用 `torch.compile` 后常见 epoch 时间约 148 秒；
- EfficientMedNeXt 的 HCC Tumor Dice/Recall 为 0.3468/0.2697，低于 MedNeXt 的 0.4175/0.3582；
- EfficientMedNeXt 的低参数量没有在当前官方实现中转化为实际训练速度优势。

尚不能写入具体数值的内容：

- EfficientMedNeXt 峰值显存为多少 GB；
- 它比主模型多占多少显存；
- 严格同条件下的训练吞吐差值。

原因：现有日志没有保存峰值显存数字。用户对其高显存占用有明确运行记忆，可作为内部 benchmark 动机，但论文正式数字必须重新测量。

正式写作建议：

> EfficientMedNeXt-L substantially reduced the parameter count, but its official implementation did not yield a corresponding wall-clock training advantage in our pipeline. Because historical runs used different compilation and multi-GPU settings, standardized runtime and memory measurements are reported separately when available.

若不做统一 benchmark，则正文只保留参数量和性能，不写实际速度/显存强结论。
