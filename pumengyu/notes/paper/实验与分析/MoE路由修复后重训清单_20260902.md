# MoE 路由修复后重训清单

> 建立日期：2026-09-02  
> 用途：记录 Baseline checkpoint 恢复和 MoE 路由修复后的正式重训，避免旧结果被覆盖或将“已启动”误报为“已完成”。  
> 主方法：`MedNeXt_MLA_MoE`。“外部可靠性”仍是待重训验证的评价问题，不是预设结论。

## 1. 为什么需要重训

这次包含两条独立的恢复链：

1. Baseline：旧 `checkpoint_best.pth` 被短试跑覆盖，无法作为正式论文来源；
2. MoE：旧 `MoEFFN.forward()` 会在 gradient checkpointing 的原始 forward 和 backward 重算中修改路由 buffer，DDP 也没有按全局 token 负载聚合。

MoE 修复后，forward 只记录当前 iteration 的专家计数；backward 完成后只提交一次 bias/EMA 更新；DDP 提交前使用 `all_reduce(SUM)` 聚合各 rank 计数。

旧 MoE checkpoint 只保留为探索性证据，不从旧 checkpoint 继训，不用旧数字替代修复后结果。

## 3. DDP 决策

### 3.1 技术上是否可以用

可以，但只能在以下门槛全部通过后作为正式训练：

1. checkpoint 与非 checkpoint 的输出、参数梯度和路由更新回归检查通过；
2. DDP 全局专家计数聚合回归检查通过；
3. 真实两卡做一个短 smoke test，记录两个 rank 的 `expert_bias` 和 `expert_load_ema` 一致；
4. 两张 GPU 均没有其他用户的任务，不挤占、不终止他人进程。

当前前两项代码级回归已通过；真实两卡 smoke test 尚未执行。

### 3.2 实验公平性

Dataset003 计划的 global batch size 是 2。nnU-Net DDP 在两卡时将其拆成每 rank 1，不是将 global batch 扩大为 4。但是单卡与 DDP 仍有进程数、样本分配、oversampling 路径和通信方式差异。

本轮默认策略：

> R1/R2 优先使用单卡顺序重训，与现有纯 MHA/MLA 核心对照的单卡条件对齐。只有决定将整个核心矩阵统一改为 DDP 时，才使用两卡正式重训。

## 4. 防覆盖策略

### 4.1 旧结果冻结

不得将修复后训练写入：

```text
/home/PuMengYu/nnUNet_workspace/results_v2
```

该目录保留旧权重、报告和可视化，用于追溯问题和对照重训前后变化。

### 4.2 统一重训暂存目录

Baseline、MLA+MoE、MHA+MoE 和后续确认需要重训的 SizeOV4 全部使用同一个根目录：

```text
/home/PuMengYu/nnUNet_workspace/results_v2_baseline_retrain_20260902
```

虽然根目录名称中有 `baseline`，但 nnU-Net 会为不同 Trainer 创建不同子目录，因此不会互相覆盖。本轮不再创建单独的 MoE retrain 根目录。

### 4.3 启动规则

- 新训练：目标 `fold_0/` 必须不存在，命令不带 `--c`；
- 中断续训：必须使用原目录并带 `--c`；
- 想重新从 epoch 0 训：先停止该 Trainer 的所有进程，确认暂存子目录已判定无效，再精确清理该 Trainer 子目录；不删整个暂存根目录；
- 启动前记录 trainer、fold、目标目录、源码版本/差异和 GPU 模式；
- 发现意外写入旧目录时，立即停止当前任务，先核对 log、checkpoint epoch/mtime 和可恢复备份，不继续生成正式报告。

### 4.4 验收后替换回正式目录

只有当某个方法的训练、checkpoint 来源、三域预测、`summary.json`、`.txt` 报告和实际可视化 PNG 全部通过后，才替换正式目录中对应的 Trainer：

```text
/home/PuMengYu/nnUNet_workspace/results_v2/Dataset003_Liver/
```

替换流程是：

1. 解析并列出新旧两个精确 Trainer 子目录；
2. 停止该 Trainer 的训练、评价和读写进程；
3. 将旧 Trainer 子目录临时改名为 `.__old_pending_delete_20260902`；
4. 将验收通过的新 Trainer 子目录移入 `results_v2/Dataset003_Liver/`的规范名称；
5. 从规范路径重新核对 checkpoint 加载、trainer/fold/epoch 和文件数量；
6. 核对通过后删除精确的 `.__old_pending_delete_20260902` 子目录；
7. 所有需重训方法都已替换后，删除已空的统一暂存根目录。

删除范围只允许是已验收方法的精确 Trainer 子目录，绝不删除整个 `results_v2`。这些删除和替换现在不执行，等完整验收时再做。
