# 论文绘图规范与工具方法

> **AI 必读：**凡设计、修改、运行或检查本论文任何图片、图注、绘图脚本、SVG 或 PNG，操作前必须完整阅读本文件。本规范适用于现有全部图片及后续新图，不只适用于图 1–5。

## 1. 总原则

1. 默认读者不了解 MedNeXt、MLA、MoE 和本仓库代码。
2. 先检查真实类、参数和 `forward()`，再绘图；不得猜测结构或为了好看改变计算顺序。
3. 图与相邻正文应共同回答：输入来自哪里、依次做什么、维度如何变化、输出到哪里。
4. 当前配置已确定时使用真实形状和层宽，例如 `[B,512,8,8,8]`、`[B,512,512]`、`512 → 1024 → 512`。
5. 一张图只回答一个核心问题；内容拥挤时增加画布或拆分子图，不缩小字体硬塞。

MedNeXt 层级拆分、残差判定、代码核对和布局模板见《[MedNeXt结构图绘制经验与检查模板](MedNeXt结构图绘制经验与检查模板.md)》。

## 2. 正式图形式

- 正式论文不得用 ASCII、Mermaid 或 `text` fenced code block 代替结构图；这些只可用于讨论草稿。
- 结构图由 Python 生成，禁止手工修改图形内容。日常个人查看的工作图默认只输出、保留 SVG；最终分析或论文使用时，再按需导出 300 DPI PNG。正式交付需要双格式时同时保留 SVG 和 PNG。
- 默认使用 Matplotlib。图 1–5 的浅色填充、深色边框、圆角矩形和深灰箭头作为全部结构图的视觉基线。
- 最小视觉语法：
  - 圆角长方形：张量、层或模块；
  - 直线箭头：数据流；
  - 圆形 `+`：逐元素相加；
  - `×n`：重复同一模块。
- 框内原则上只放两层信息：粗体模块名和一行关键维度或作用。
- 结构总览图中的张量形状统一使用普通正体文本（例如 `[B,64,D/2,H/2,W/2]`），不使用数学斜体；维度含义和“该形状是输入还是输出”统一放在图注说明，避免在色块内重复堆叠。
- 同类语义使用相同名称、大小写和颜色；不能只靠颜色传递含义。

颜色语义：

- `feature`：三维特征；
- `token`：序列表示；
- `latent`：低秩表示及 K/V 投影；
- `block`：主要计算模块；
- `moe`：路由或聚合；
- `expert`：独立专家；
- `output`：模块输出。

## 3. 布局与连线

1. 默认从上到下阅读。信息增多时优先增加纵向空间。连续的 Transformer Block 沿同一竖直主轴上下串联，不为了维持画布高度把每个 Block 强行横排，再用长折线从右端绕回下一行左端。局部短算子链可以横排，但不得迫使主流程反复折返。
2. 箭头必须有可见线段和完整箭头头部，不得贴文字、穿色块、压边框或倾斜重叠。每条短箭头至少应保留一段可辨认的箭身，不能只剩贴在框边的箭头尖；这也是 AI 自动绘图最常见的版式缺陷之一。
3. 加号上下必须分别保留完整箭头空间；skip/identity 箭头终止于加号边界。
4. 能直连就不转弯；必须绕行时只用水平/垂直正交线，并采用最少转角。
5. 多个输入进入同一模块时优先分别垂直进入，避免在入口上方堆叠折线。
6. 重复 stage 的框高、节点大小、箭头长度和间距必须一致。
7. 外层流程与内部 block 放在一起变拥挤时，拆成独立子图并分别配图注。总览中的模块展开用新增子图承载，例如图 D 展示 Transformer 串联，图 E 展示 MoE-FFN 内部；标明展开模块的输入来源和输出返回位置。
8. 连线端点按实际边界计算：从上方矩形的下边缘指向下方矩形的上边缘；进入圆形 `+` 时指向圆周，离开时从圆周起笔。不得把加号当作矩形，或给整组箭头套用未经核对的坐标偏移。
9. 用 `FancyArrowPatch` 画短箭头时，同时检查模块间距、箭头头部大小和 `shrinkA`/`shrinkB`。默认端点收缩可能吃掉短线段；端点已精确落在边界时可设 `shrinkA=0, shrinkB=0`，但仍须留出可见的箭身和完整头部。空间不足就拉开模块或增加画布。检查加号的输入和输出两侧；跨 Block 连线必须实际接到下一个输入框，不能停在容器边缘。标题与连线说明应避开主轴，不能盖住箭头。
10. 字号必须先按最终单栏/双栏毫米宽度换算：`final_font_size = source_font_size × final_width / exported_width`。设定最终最小字号后再反推源字号；空间不足时删减重复文字或重排模块，不能靠无限缩小字体解决。这是 AI 架构图第二类常见缺陷。
11. 局部终点拥挤但周围存在明显空白时，优先把相关计算框、合并节点和依赖线作为一个布局组整体平移；不要把修复等同于缩短最后一根箭头。平移后重新计算组内外全部端点，并检查是否形成新的短箭头或无意义折线。

以上规则推广到全部结构图和流程图；后续修改任一旧图时必须一并检查，不得只修用户指出的单个节点。

## 4. 结构正确性

### MedNeXt

- Decoder 顺序必须是 `UpBlock → 与 skip 相加 → MedNeXtBlocks`。
- 卷积类型、stride、通道数、重复次数和输出尺寸必须与代码一致。

### MLA

- 区分共享低秩表示与两个独立 K/V 投影。
- `128 → 512` 应称为 `K/V projections`，不能称为“恢复信息”；上投影不会找回压缩时丢失的内容。
- 正文同时说明优势与边界：参数减少，但可能损失信息；分割任务没有自回归 KV cache 优势；完整注意力仍为 $N^2$。

### MoE

- shared expert、专家选择器（标准 MoE Router）和 routed experts 必须在视觉上分开；专家选择器不是 expert。
- shared expert 始终计算；专家选择器产生分数并选择 top-2；选中的 routed outputs 加权后与 shared output 相加。
- balance bias 只影响 top-2 选择；当前实现先按选中索引 gather 原始 scores，再对这两个分数做 softmax 得到 gate weights。图中分别画出索引和原始分数的依赖，不能画成对全部专家 softmax 后直接截取。
- 以 `MoEFFN.forward()` 为准：当前实现先计算全部 4 个 routed experts，再 gather Top-2 输出。不得将“选中两个输出”画成“只计算两个专家”，也不能把 shared expert 或 router 的输出接成 routed experts 的特征输入；三者接收同一份输入特征。
- 展开单个专家时核对真实层：当前为 Linear → GELU → Dropout → Linear → Dropout；图示配置为 512 → 1024 → 512。共享专家与路由专家结构相同、参数独立；MoE 内部的 shared + routed 与 Transformer 外层 residual add 必须区分。

### 张量操作

- `reshape`、`flatten` 和 `transpose` 只改变排列，不得画成卷积、线性层或可学习模块。
- `token` 指 bottleneck 特征图中一个空间位置的特征向量，不是自然语言词语。

## 5. 正文与图注

- 正文补充原因、优点、缺点、质疑和实现边界，不重复抄写图中流程。
- 缺少严格消融时，不得把性能变化单独归因于某个低秩、路由或注意力组件。
- 图注位于图片之后，使用：

```html
<p style="text-align: justify;"><small><strong>图 n  标题。</strong> 说明文字。</small></p>
```

- 图注采用小字号、两端对齐和自然换行；禁止整段居中或强制 `<br>`。
- 多子图分别编号为图 n(a)、图 n(b)，并各自紧跟图片。

## 6. 输出与检查

源代码放在 `figure_factory/`，成品放在 `figures/`，正文引用 SVG。

每次交付前必须完成：

- [ ] 真实结构、名称和维度与代码一致；
- [ ] 字号在论文实际宽度下可读；
- [ ] 箭头、转角、加号和色块不拥挤；
- [ ] 逐段核对箭头起终点是否落在模块或加号的正确边界；在预期阅读尺寸及放大后都能看到箭身和箭头头部；
- [ ] 同类模块的颜色与间距一致；
- [ ] Python 脚本可编译；
- [ ] SVG 可解析；
- [ ] 按需导出的 PNG 为 300 DPI；
- [ ] 实际渲染并目视检查；日常 SVG 可使用临时预览，不必保留 PNG，正式导出 PNG 时须检查该 PNG；
- [ ] 正文图注格式正确且引用正式 SVG。
